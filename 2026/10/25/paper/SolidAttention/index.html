SolidAttention：内存受限 PC 上的低延迟 SSD 辅助 LLM 推理

论文：SolidAttention: Low-Latency SSD-based Serving on Memory-Constrained PCs，Xinrui Zheng、Dongliang Wei、Jianxiang Gao、Yixin Song、Zeyu Mi、Haibo Chen，上海交通大学并行与分布式系统研究所（IPADS），FAST ‘26（24th USENIX Conference on File and Storage Technologies），2026。论文页。

TLDR： 系统将键值缓存存于 SSD；块级稀疏按块选取参与计算的缓存，逐 token 交错存放键/值；历史预取、微任务调度降低 I/O 阻塞。128k 下较 Offload+Sparse 快至 3.1×、缓存占用最多降 98%，精度近 FP16。

一、背景：AI PC 的 KV cache 容量约束

本地部署 LLM 有隐私、定制与成本优势，AI PC（AI personal computer，AIPC）随之兴起。市场分析显示，目前出货的多数 PC 配备 8–16 GB DRAM，GPU 多为集成显卡（integrated GPU，iGPU）或配有 6–8 GB 显存（VRAM）的入门级独显。模型推理的主要内存开销来自 KV cache（key-value cache，键值缓存）：它随上下文长度线性增长。论文指出，128k token 已成为默认上下文配置；Llama-3.1-8B 的 INT4 权重在该长度下，KV cache 本身就超过 16 GB，是权重占用的 4 倍以上。decode（解码）每步只生成一个 token，算术强度低、对延迟敏感，因此长上下文推理受 KV cache 容量限制。

上下文长度和传输单元对内存占用及 SSD 随机读吞吐的影响（Figure 1: (a) The memory usage of model and KV cache as the input length grows. The model is Llama-3.1-8B quantized in INT4. (b) Random read throughput of SSD with various transfer unit sizes.）

注意力稀疏（attention sparsity）利用少数 token 对输出影响较大的特点，只让相关 KV 对参与计算。静态方法在 prefill（预填充）后筛除部分 KV 对：SnapKV 用 prefill 末尾的观察窗口识别重要 token；StreamingLLM 则指出注意力汇（attention sink）现象，即初始 token 会累积不成比例的注意力权重。由于静态方法依据当前 query 永久驱逐 KV 对，后续 token 可能需要的信息也会随之丢失。

动态方法保留完整 KV cache，并在 decode 阶段按层选择 KV 块。Quest 根据每块 key 向量的 max/min 值构造代表向量；InfLLM 按 query 与块代表向量的相似度选取 top-k 块。由于后续会访问哪些块事先未知，整份 KV cache 仍须驻留内存，动态稀疏本身不能降低这部分内存占用。

SSD（solid-state drive，固态硬盘）卸载打破容量限制：SSD 可提供 TB 级存储，足以容纳完整 KV cache；推理时按需读取关键块。这留下读取时机和访问粒度两个问题。

二、现状：本地低并发下的 SSD 延迟

FlexGen 代表了现有 SSD 卸载路线：之字形（zig-zag）调度批量请求，用其他并发请求的计算工作负载隐藏 KV cache 加载。这依赖足够高的请求并发；本地 decode 通常是单请求、batch 1，计算远快于 I/O，SSD 访问延迟因而暴露出来。从 SSD 加载 1k-token 的 KV cache（128 MB）约需 40 ms，接近一个 decode 步时长的一半。

更深层的冲突在访问粒度。SSD 只有较大的传输单元才能跑满带宽；小请求也难以利用通道并行（channel parallelism）等 SSD 内部并行性。动态稀疏注意力则产生细粒度、动态的访问：本层要选哪些块，须到注意力计算前一刻才能确定。两者错位会降低 SSD 利用率，也压缩 I/O 与计算的重叠空间。

不同请求并发度下批处理隐藏 SSD 访问延迟的对比（Figure 2: Comparison of hiding SSD access latency by batching requests under different request concurrency.）

把稀疏与存储当两个独立问题处理，会遇到三个挑战：

  1. 精度损失：块级选择依赖每块的代表向量。块越大，单个代表向量概括的 KV 对越多，召回率越低；块越小，细粒度访问越难利用 SSD 带宽，I/O 延迟也会上升。
  2. 预取不确定性：本层的选择在注意力计算前不可知，因此不能直接提前预取；而从 token 选择到自注意力计算之间留给 SSD I/O 的时间不足，加载延迟会暴露在 decode 步中。
  3. 数据不一致：若计算和预取并发访问同一 KV 缓冲区，GPU 正在读取的当前层数据可能被下一层异步预取覆写。

三、优化点：降低单请求的 SSD 阻塞

论文要降低单请求 decode 的 SSD 阻塞延迟，同时控制块级稀疏对召回率和 KV cache 内存占用的影响。

四、方案：SolidAttention 的协同设计

SolidAttention 把完整 KV cache 保存在 SSD，推理时按需将所需数据加载到 GPU 内存。

SolidAttention 系统架构（Figure 3: Architecture overview of SolidAttention.）

Figure 5 展示单层 KV cache 的数据流：本层预测块先从 SSD 加载到 VRAM；完成块选择后，再从 SSD 加载未命中块，同时 GPU 计算当前 token 的新 K/V 对并写入 DRAM；自注意力计算期间，系统预取下一层的预测块至 DRAM；随后在前馈网络（feed-forward network，FFN）计算期间将其加载到 VRAM，并把新 K/V 对写回 SSD。

单层 KV cache 的数据流编排示例（Figure 5: An illustrative example of how SolidAttention orchestrates the dataflow over the KV cache for a single LLM layer.）

4.1 KV cache 分块与代表向量

KV cache 沿上下文维切成三类块：init blocks 覆盖初始 token，用于保留注意力汇；local blocks 覆盖最近的 token；selected blocks 根据当前 query 动态选择。decode 时，系统确定性预加载 init/local blocks，再根据 query（Q）与块代表向量的相似度选出 top-k selected blocks。SolidAttention 沿用 InfLLM 的代表向量设计，从每块的 key（K）缓存提取代表向量，与当前 query 计算点积。

块级动态注意力稀疏中的 KV 分块和选择（Figure 4: Partitioning and selection in SolidAttention’s block-wise dynamic attention sparsity. A representative vector is extracted from each block’s K cache and dotted with the query Q to obtain similarity scores. The blocks with the top-k scores (blocks 1 and 3) are selected to participate in the attention computation, together with the init block (block 0) and the local block (block 4).）

4.2 K/V 交错布局与权重预拼接

更大块可提高 SSD 传输效率，但会降低块级选择的召回率。SolidAttention 因而在 token 粒度交错 K/V 对，不增加每块的 token 数，也能合并数据传输。权重预拼接是指模型初始化时离线合并 K、V 两组投影权重。

不同块大小下 PassageRetrieval-en 与 PassageRetrieval-zh 的召回率（Figure 6: Comparison of the recall rate under PassageRetrieval-en (en) and PassageRetrieval-zh (zh) workloads from LongBench [8] as block size varies.）

分离式与交错式 KV cache 布局下的存储操作（Figure 7: Comparison between operations with separate KV cache layout (Typical) and interleaved KV cache layout (Interleaved).）

  • 传输：交错把 K、V 两次独立访问合并为一次聚合传输，传输单元翻倍、I/O 次数减半；块内 token 数不变，因此无需以牺牲召回率换取带宽利用率。
  • 投影计算：分别计算 K、V 投影需要额外重排；预拼接后的权重可通过一次矩阵乘直接生成交错的 K/V 对，无须后处理。
  • 注意力计算：PyTorch 和 llama.cpp 支持跨步访问；注意力核按 2H（H 为隐藏维）步长读取交错缓冲，在逻辑上区分 K 与 V，无须物理重排；相较连续布局的延迟开销不超过 2%。

使用分离权重与预拼接权重生成交错 KV cache 的投影计算（Figure 8: Comparison between projection computations generating interleaved KV cache with separate weights (Typical) and pre-concatenated weights (Interleaved).）

4.3 历史选择驱动的投机预取

论文在 LongBench 多个模型与任务上测得，相邻迭代的块选择结果平均相似度约为 81%（1k-token 上下文预算）。Speculative Prefetcher（投机预取器）记录每层上一轮的选择结果，并利用注意力计算期间空闲的 SSD 带宽，预取这轮可能再次选中的块；未命中的块仍从 SSD 加载。

1k 上下文预算下相邻迭代的块选择相似度（Figure 9: Average similarity of selection results across consecutive iterations, evaluated across models and benchmarks in LongBench, with a 1k context budget）

自注意力只要求每个 token 的 K/V 对在同一位置对齐，不要求 token 在 KV cache 中保持全局顺序。系统将误预取块标记为无效，再由新加载的块直接覆写；有效块保持原位。这避免了对已取块重新排序、复制或额外分配内存。

历史选择驱动的缓存预取与缺失块覆写（Figure 10: (a) init block (block 1) and local blocks (blocks 8 and 9) are deterministically prefetched, while selected blocks (blocks 4 and 6) are prefetched according to the historical selection results of the preceding iteration. (b) After formal selection and the selection result is corrected, the missing cache block (block 3) is loaded from SSD and the incorrectly prefetched block (block 6) is directly overwritten.）

4.4 微任务 DAG 与同步点复用

有限的 DRAM 缓冲区既要供计算使用，也要容纳 SSD I/O 数据。多层缓冲可以隔离并发访问，但内存受限的 PC 难以承担其开销；共用缓冲又可能让预取覆写 GPU 正在读取的数据。将 I/O 全部串行化会使 GPU 空闲，而稀疏注意力频繁的 GPU–SSD 交互还会增加同步开销。调度器据此将计算与 I/O 拆成微任务，并按数据依赖连成有向无环图（directed acyclic graph，DAG）；非关键任务复用关键任务的同步点，以减少同步开销。

单层注意力模块及 I/O 操作的时间线（Figure 11: The timeline of the attention module and I/O operations in one LLM layer. Operations with data dependencies are connected by arrows. Sync denotes synchronization between CPU and GPU.）

  • 微任务分解与细粒度重叠：调度器按数据依赖拆分注意力模块，包括 query 投影（q_proj）、K/V 投影（kv_proj）、写入新 KV 对（store）、预取与选择（prefetch、select）、加载缺失块（load）和自注意力计算（attention）；I/O 继续按 KV 块细分。关键路径是决定理论最小延迟的最长依赖链，调度器优先执行关键路径上已就绪的任务，并尽早发起非关键 I/O 与 GPU 计算重叠。例如，select 只依赖 q_proj，所以后者完成后即可开始选择；缺失块的 load 与 kv_proj 并行，以隐藏 I/O 延迟。
  • 同步点复用：关键任务（如块预取）决定延迟，非关键任务（如新 KV 写回）可延后。CPU→SSD 写回与下一层预取都在前一轮 GPU 自注意力计算完成时同步，因此写回无需单独设置同步点。selected blocks 与 init/local blocks 可分别传输；自注意力开始前，调度器复用缺失块加载的同步点确认这些传输完成，避免额外状态跟踪。

集成显卡（iGPU）采用统一内存，CPU 与 GPU 共享内存空间。KV cache 放入统一内存后，DRAM 与 VRAM 之间无须显式搬运，可减少设备间握手并简化流水线。

4.5 实现与运行参数

SolidAttention 基于 llama.cpp 实现，使用 liburing 处理 SSD I/O，共约 25k 行 C++ 与 CUDA 代码，其中 12k 行为 GPU 核、1k 行为 llama.cpp 适配层；论文在 Llama 和 Qwen 模型上验证了系统。两个专用 CPU 核分别处理 I/O 和 SSD–GPU 协调。KV cache 的频繁写入会造成写放大；论文报告其性能开销相较读取可忽略，并为减少 SSD 磨损，在每层设置 32 KB 写缓冲以合并写入。

输入短于 4k token 时，上下文预算取输入长度的 25%；否则固定为 1k。预算的一半分给 init/local blocks，另一半分给 selected blocks；块大小为 32 个 token。

五、结果：性能、内存与精度

5.1 实验平台、模型与基线

实验使用两台 Linux 笔记本。CUDA 后端配置为 16 核 Intel Ultra 9 185H、RTX 4070 Laptop GPU（8 GB GDDR6），内核版本为 v6.8.0、CUDA 版本为 12.8；SYCL 后端配置为 16 核 Intel Ultra 7 255H、Intel Arc 140T 集成显卡，内核版本为 v6.11.0、oneAPI 版本为 2025.0。两台笔记本均配有 64 GB DDR5 和 1 TB Samsung 990 Pro PCIe 4.0 SSD。

评测模型为 Llama-3.2-3B、Llama-3.1-8B 和 Qwen-2.5-7B，模型权重均为 INT4，KV cache 为 FP16。Qwen-2.5-7B 的 KV cache 容量是 Llama-3.1-8B 的一半，但 FFN 计算量更大。

基线包括 Offload（完整 KV cache 卸载到 SSD）、Offload+Sparse（在 Offload 上集成 InfLLM 稀疏注意力）和 FlexGen（按注意力分数选择性加载 KV cache）。FlexGen 原生只支持 OPT，论文将其扩展到 Llama 和 Qwen。所有实验的 batch size 为 1、最大输出长度为 512 token、DRAM 上限为 16 GB；FlexGen 的注意力稀疏比例（attention sparsity ratio）设为 10%。

5.2 系统性能、精度与资源开销

端到端测试使用 WikiText-2 数据集的截断提示。CUDA 后端上，FlexGen 在上下文长度超过 16k 时发生 CUDA 内存不足（out of memory，OOM）。128k 上下文下，SolidAttention 相较 Offload+Sparse 在 Llama-3.2-3B、Llama-3.1-8B 和 Qwen-2.5-7B 上分别加速 2.8×、3.1× 和 2.4×；16k 上下文下，相较 FlexGen 的最高加速比为 58.9×。SYCL 后端相较 Offload+Sparse 的最高加速比分别为 2.1×、2.5× 和 1.9×。

输入长度超过 4k 后，Offload+Sparse 和 SolidAttention 的延迟趋于稳定；论文将其归因于稀疏注意力同时减少 KV 访问和计算量。FlexGen 则因缺页引发大量细粒度 SSD 访问，浪费带宽，且小 batch 的计算量不足以隐藏 I/O 延迟。

在更大的模型上，SYCL 后端运行 INT4 量化的 Qwen2.5-14B。FFN 计算量较大，削弱了延迟收益；但在 128k 上下文下，SolidAttention 仍将 KV cache 内存占用减少 98%，并较 Offload+Sparse 获得最高 1.7× 加速。收益取决于 I/O 与计算量的比例，而非模型的绝对内存容量。

内存占用。 相较于完整 KV cache 驻留 DRAM，SolidAttention 仅需为一层、1k-token 上下文的 KV cache 分配缓冲；Llama-3.2-3B、Llama-3.1-8B 和 Qwen-2.5-7B 的占用分别最多降低 61.9×、62.0× 和 61.9×。代表向量的额外存储相较完整 KV cache 可以忽略。

机制消融。 三组实验分别测量投机预取、交错布局和调度器的贡献：

  • 投机预取（WikiText-2 的 16k 提示，测量 KV cache 加载造成的阻塞延迟）：SYCL 后端最高降低 3.1×，CUDA 后端最高降低 3.9×。Qwen-2.5-7B 的 KV cache 较小、I/O 延迟占比也较低，因此对应收益为 2.9× 和 1.9×。
  • 交错布局（CUDA，SSD 为瓶颈）：注意力延迟最高降低 22%，归因于 CPU-GPU 与 SSD-CPU 间带宽利用率提高且无额外数据拷贝；对核内注意力计算的影响可忽略。
  • 调度器（SYCL）：细粒度重叠最高提升 25%，因为计算可与缺失块加载重叠；同步点复用再降低 22% 的注意力延迟。计算量较大的 Llama-3.1-8B 上，同步点复用收益较弱，因为计算掩盖了同步节省的固定延迟。

敏感性分析。

  • 上下文预算：预算低于 4k 时，I/O 大多与计算重叠，注意力延迟随预算缓慢上升；预算达到 4k 后，I/O 超出可掩盖范围，注意力延迟明显上升。论文 §8.3 定性称 1k 预算下的长上下文精度损失可忽略，但未给出具体差值；实现中对输入长度不短于 4k 的请求采用 1k 预算。
  • 块大小：块大小为 32 时的吞吐比 16 高约 14%，因为较大块更好地利用 SSD 并行性；分块更细会增加随机 I/O 开销。超过 32 后传输量已足以跑满带宽，吞吐与注意力延迟趋平。
  • SSD 配置：SSD-high（Samsung 990 Pro，7.5 GB/s、1.2M IOPS，即每秒输入输出次数）与 SSD-low（KIOXIA BG6，5.0 GB/s、650k IOPS）对比。在 4k 上下文预算下，I/O 需求超过可用带宽后成为瓶颈：SSD-low 尾延迟上升 45%，SSD-high 保持稳定。1k 预算下两者平均延迟相近；输入长度增加时，两款 SSD 的尾延迟都保持稳定，论文将其归因于预取和调度对计算、I/O 的重叠。

I/O 干扰。 在 CUDA 后端使用 fio 模拟后台负载：顺序读以 4 GB/s 施加带宽型干扰，4 KB 随机读以 800k IOPS 施加 IOPS 型干扰。两种负载分别使 SolidAttention 吞吐下降 58% 和 54%。可用带宽越少，它与 Offload+Sparse 的性能差距越小；论文将其归因于 SolidAttention 更充分地利用带宽，因此对带宽短缺更敏感。

并发 I/O 负载下 CUDA 后端的推理吞吐（Figure 20: Inference throughput on the CUDA backend under concurrent I/O workloads.）

带宽型干扰下，论文正文报告平均延迟升至 2.4×、99.9 分位延迟升至 2.9×；但 Figure 21 图注标为 P99，两处口径不一致。IOPS 型干扰下延迟波动较小；由于多个 token 会摊销单次延迟，端到端请求延迟受影响较小。

并发 I/O 负载下 CUDA 后端的平均和 P99 推理延迟（Figure 21: Average and P99 inference latency of SolidAttention on the CUDA backend under concurrent I/O workloads.）

能耗。 论文以 GovReport 摘要提示测量能耗，输入长度平均为 10k token。SolidAttention 峰值功耗为 36.27 W，高于 llama.cpp 的 32.98 W（论文归因于 SSD 访问）；每 token 能耗分别为 3.68 J 和 5.37 J。论文称能耗降低 46%，但按表中数值计算，降幅约为 31.5%。
