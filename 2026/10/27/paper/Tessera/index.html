论文：Tessera: A Holistic Pipeline Parallelism Framework for Trillion-Parameter Heterogeneous MoE Training，Weifang Hu（华中科技大学）、Langshi Chen、Man Yuan、Youyang Yao、Xiulong Yuan、Li Tian、Yong Li、Wei Lin（阿里云）、Xuanhua Shi（华中科技大学）、Zhengping Qian、Jingren Zhou（阿里云），OSDI ’26（Operational Systems，2026）。Weifang Hu、Langshi Chen、Man Yuan 共同第一作者；Xuanhua Shi 与 Zhengping Qian 为通讯作者。论文：USENIX PDF。

TLDR： Qwen3-Next 等异构 MoE 模型同时包含不同注意力层和稀疏专家层，固定的通信重叠模板与按串行耗时划分流水线会产生不均衡；MoE 路由的 token 数量还会让静态计划留下不可预测的空闲槽。Tessera 为每种层组合合成并实测细粒度重叠调度，再以重叠后代价联合选择分区；运行时则根据路由统计，把可延后的权重梯度等任务填进预测空闲槽。阿里生产集群上的五组 Qwen3/Qwen3-Next 预训练负载使用 4,096–12,288 张 NVIDIA Hopper GPU，论文报告吞吐提升 20%–33%；表中对应的 MFU（Model FLOPs Utilization，模型 FLOPs 利用率）相对提升为 20.0%–32.8%。其中 Qwen3-XL 在 8,192 张 GPU 上达到 39.0% MFU。另在 256-GPU 的公开配置对照中，Tessera 在 Qwen3-235B 上的 MFU 达到 Megatron-Core MoE 的 1.24×。

一、背景：异构 MoE 与流水线成本

Mixture-of-Experts（MoE）把一层中的计算分配给多个专家；每个 token 根据路由结果只激活其中一部分专家。专家分布在不同设备上时，token dispatch 和结果 combine 需要 All-to-All（A2A）通信。集群扩大到数千张 GPU 后，A2A 在迭代时间中的占比上升，流水线系统需要把它与其他 microbatch 的计算重叠，才能减少暴露在关键路径上的通信等待。

Qwen3-Next 把 Gated DeltaNet（GDN）线性注意力与标准 softmax 注意力按每四层 3:1 交错排列，每种注意力层后都接稀疏 MoE。生产序列长度下，相邻注意力操作的计算时间最多可相差 10 倍；MoE 路由也很稀疏，每个 token 只激活 512 个专家中的 10 个。不同层组合因而有不同的计算量、A2A 通信量和重叠空间。

Qwen3-Next 的混合注意力层组成（Figure 1: Heterogeneity in Qwen3-Next Architecture. (a) standard Transformer layer; (b) Qwen3-Next interleaves Gated DeltaNet and standard attention layers.）

流水线并行（pipeline parallelism，PP）按模型层把网络切成 chunk（连续层组成的模型分段），再将 chunk 分配给流水线阶段。训练批次拆成 microbatch（微批次）后，不同阶段可以同时处理不同 microbatch；常用的 1F1B 调度在每个阶段交替执行一个前向和一个反向 microbatch。交错式 1F1B 还会给一个物理 rank 分配多个虚拟阶段，使同一 rank 上不同 chunk 的操作能够来自不同 microbatch。Tessera 把一个 chunk 的通信与另一个 chunk 的计算并行执行称为 inter-microbatch overlap。

跨 microbatch 的通信与计算重叠（Figure 2: Mechanism of Inter-Microbatch Overlap. The bottom panel illustrates how the backward pass of Chunk B is overlapped with the forward pass of Chunk D by interleaving decomposed operations.）

二、问题：异构流水线重叠调度挑战

2.1 异构层组合的重叠对

交错式流水线中，一个虚拟阶段会与同一 rank 上其他阶段形成重叠机会。重叠对不仅由两个 chunk 决定，也要区分各自的前向或反向方向；例如，某 chunk 的反向与另一 chunk 的前向，和反过来的方向，是不同的调度情形。Qwen3-Next 的异构 chunk 会产生多种计算—通信比例不同的重叠对。即使只有两个流水线阶段，也可能出现八种 pair 类型，各自需要不同的任务交错方式。固定地把某类通信任务与某类计算任务配对，不能适配所有组合。

论文按 attention/MoE 组成把 chunk 类型标为 A–D：C 型包含三个连续 GDN 层，D 型包含标准注意力层和 output head；示意中的注意力层后续 MoE block 未画出。因此，C–C 和 D–D 分别表示两个同类型 chunk 组成的重叠对。

已有 intra-microbatch overlap 通过切分同一 microbatch 的 token 来隐藏 MoE 通信，但序列切分会把 GEMM（general matrix multiplication）分成更小的操作，降低计算强度；用 kernel fusion 补回效率又会增加 MoE kernel 与通信后端之间的耦合。inter-microbatch overlap 保留完整 GEMM 的计算强度和后端模块性，但要求系统能针对具体 chunk 组合拆分任务并安排顺序。

异构 chunk 形成的多种重叠对（Figure 3: Combinatorial Explosion of Overlap Patterns. The Qwen3-Next architecture produces asymmetric chunks, resulting in diverse overlap pairings that require structurally different fine-grained plans. For clarity, MoE blocks following the GDN and standard attention are not shown.）

2.2 串行分区与重叠代价

传统分区器按各层串行执行时间求和，尽量平均分到每个阶段。这隐含假设是各阶段隐藏通信的效率相近。异构模型不满足这一点：论文在 Qwen3-Next-80B 的 8 层训练、256K 序列长度、128 张 GPU 上测得，C–C 重叠对的延迟降低 41.6%，D–D 重叠对只降低 14.0%。计算—通信互补的组合能隐藏更多 A2A；两侧都由计算主导时，可隐藏的通信较少。

因此，串行耗时相近不代表流水线并行后的阶段耗时相近。在同一组 profile 中，按串行成本平衡的分区，其瓶颈重叠后代价（post-overlap cost）比 Tessera 的重叠感知分区高 1.14 倍。分区决定会出现哪些重叠对，而重叠调度的效果又决定哪些分区更均衡；先固定分区再套统一重叠模板，无法解决这组相互依赖的问题。

不同分区的重叠效率与瓶颈代价（Figure 4: Impact of Variable Overlap Efficiency. Variation in overlap gains under two partition plans. Data collected from training 8 layers of the Qwen3-Next-80B model with sequence length 256K on 128 GPUs. Left: A partition balanced for serial execution becomes imbalanced in post-overlap execution. Right: Tessera’s overlap-aware partitioner finds a plan that balances the post-overlap cost.）

2.3 路由波动与流水线空闲

静态计划还无法准确预知每轮路由会把多少 token 分配给各专家。每轮每个 rank 收到的 token 数会变化，专家计算时间随之波动，形成短暂的本地空闲槽或跨设备等待；这类流水线空闲时段称为 bubble。由于 Qwen3-Next 每个 token 只路由到 512 个专家中的 10 个，较低的路由覆盖率会放大每个专家和 rank 的 token 数波动。静态分区可以平衡可预测的结构成本，却不能预先安排这些瞬时空闲。

训练迭代间的设备 token 负载变化（Figure 5: Runtime Token Load Variation. The distribution of received tokens per device varies across iterations, creating dynamic imbalance that static planning cannot address.）

三、方案：流水线分区与重叠调度优化

3.1 流水线重叠图与候选分区

Tessera 固定训练框架给定的高层流水线模板（例如交错式 1F1B），再在该模板内联合优化分区与重叠调度。静态规划分三步：先从模板构造重叠图并为每个虚拟阶段生成候选 chunk；再为图中每条边上的候选层组合合成调度并测量重叠后代价；最后选择分区并生成执行计划。

重叠图的节点是虚拟阶段，边表示模板允许在同一 rank 并行执行的两个阶段操作。边还记录前向或反向方向；同一阶段不同 microbatch 之间的重叠机会用自环表示。Tessera 先从串行耗时平衡的分区出发，在各阶段附近扰动连续层边界，得到有界的候选 chunk 范围，以控制后续 profile 和优化规模。

重叠感知静态规划流程（Figure 6: Overlap-aware static planning workflow.）

3.2 重叠任务调度与硬件代价评估

Tessera 把重叠对中的两个 chunk 分解为任务 DAG（directed acyclic graph，有向无环图）。每个任务有持续时间、资源类型（计算或通信）和依赖关系。事件驱动调度器优先安排关键路径上的 backbone task；在主干调度期间，movable task 只放入不延长重叠对 makespan（该重叠对从开始到全部任务完成的总时长）的空闲窗口，否则先延期。主干安排完成后，调度器再按 best-fit 将延期任务回填到其生命周期内的剩余空隙；仍无合适空隙的任务按算法放到执行队列尾部。

论文将这个事件驱动调度器与整数线性规划（integer linear programming，ILP）求得的参考解比较。事件驱动调度器先用可快速执行的启发式为候选对生成计划，再把候选计划放到参考设备组上运行，取得真实硬件上的重叠后代价。实际 profile 能反映硬件干扰，因此优先于只从任务 DAG 时长推算出的解析代价。

重叠对任务 DAG 与细粒度调度（Figure 7: Decomposing an overlap edge into task DAGs and synthesizing a fine-grained overlap schedule. The figure highlights one forward–backward overlap edge on Rank 0, omitting other pass-direction edges. Each stage contains a single layer for clarity.）

3.3 重叠代价驱动的分区选择

分区器为重叠图的每个节点选一个候选 chunk，并以所有已选重叠对中的最大重叠后代价为目标，寻找瓶颈代价最低的组合。混合整数线性规划（mixed-integer linear programming，MILP）还约束层范围连续且互不重叠、设备拓扑兼容和每 rank 的显存容量。高于原始串行平衡计划瓶颈代价的候选对会被安全剪枝；若某候选阶段因此没有有效相邻组合，也从搜索空间移除。

profile 在与目标 rank 使用相同 GPU 类型、tensor parallelism（TP）与 expert parallelism（EP）拓扑的参考设备组上运行。相同层范围、方向和拓扑的重叠对只测量一次，并按 model-parallel device mesh（模型并行设备布局）类别与 chunk 规格缓存。执行计划随后把所选分区和每种重叠对对应的细粒度调度写入高层流水线模板。

3.4 路由空闲槽的运行时填充

Dynamic Bubble Optimizer（DBO）处理静态规划无法预测的路由波动。静态计划会在 MoE 计算任务之后标注潜在插入点；运行时，Tessera 复用 expert dispatch 前已生成的路由元数据，在每个 EP group 内交换每个专家的 token 计数，以估计 rank 的负载偏差和空闲槽大小。交换的是标量计数，并搭载在已有 MoE dispatch 路径上，不需要全集群同步。

DBO 从有截止时间余量的 movable-task pool 中选任务填槽，主要包括已离开关键路径的 Wgrad（weight-gradient，权重梯度）任务。调度器同时考虑任务时长能否贴合空闲窗口，以及离截止时间还有多少余量。若任务接近截止时间仍未找到可用空闲槽，就把它放回主执行流，保证任务按时完成。pool 受每 GPU 配置上限和可用显存约束；达到上限后，新任务不再延后。槽位估算与任务选择异步执行，合计开销低于 10 µs。

DBO 的动态空闲槽填充（Figure 8: Dynamic scheduling of movable tasks into bubbles.）

3.5 训练框架接入与微批次补齐机制

Tessera 以独立库接入阿里内部 Megatron-LM，实现约 11,000 行 Python 和 2,000 行 C++。C++ plan-agnostic execution engine 用无锁有限状态机解释执行计划，前向和反向线程在轻量 probe 处交出控制；框架通过 advance 标记普通任务边界，用 register_task 注册可移动任务，不必把张量计算迁出原训练代码。另一个后台线程按计划执行已注册的 movable task，例如 Wgrad。调度计划也可由 YAML 指定，供用户覆盖自动合成的重叠顺序。论文称系统自 2025 年 4 月起持续用于生产训练。

交错式 1F1B 通常要求每轮 microbatch 数能被流水线并行度整除，但全局批次大小受收敛配置约束、流水线并行度受显存约束。Tessera 通过 microbatch padding 加入不执行计算、只传递伪张量的 shadow action，以满足流水线结构依赖；这些操作不进入 loss、梯度缩放或优化器计数。

静态计划针对一个 model-parallel device mesh 生成，再复制到数据并行 rank；DBO 只在各自 EP group 内运行，因此扩展到更多副本不需要跨副本协调。

四、评估：生产性能与系统开销

4.1 Qwen3 生产集群的吞吐与 MFU

生产评估使用阿里集群，每台服务器配 8 张 NVIDIA Hopper GPU，通过 RDMA over Converged Ethernet（RoCE）高性能网络互连。生产负载使用内部与开源数据集。每组均在相同集群配置和超参数下运行启用与未启用 Tessera 的训练。生产基线不是原生默认配置，而是阿里内部 Megatron-LM 分支：它已经使用交错式 1F1B、原生通信重叠和经专家调优的 FLOPs 平衡分区。

在一条 8,192-GPU Qwen3-XL、为期两周的生产 trace 中，4 月 9 日部署静态规划后吞吐立即提高约 13%，其中约 9% 来自阶段负载平衡，其余来自隐藏 A2A 通信；4 月 16 日再启用 DBO 后，MFU 达到 39.0%。

4.2 计算通信比例与重叠收益

Qwen3-Next-L 的一次 8,192-GPU 运行每轮 9.886 秒。稳态流水线中，暴露的 EP 通信占迭代时间 4.7%，bubble 占 3.7%；计入 warmup 与 cooldown 后，Tessera 隐藏了 73% 的 EP 通信，暴露 EP 通信为 8.3%。包括阶段不均衡与结构性 warmup/cooldown 在内，bubble 合计占 8.5%（366 ms 与 469 ms），暴露 EP 通信和 bubble 合计仍占迭代时间约 17%。

另一条独立的 5,120-GPU Qwen3-Next-M 运行每轮 7.147 秒；它与表中 4,096-GPU 生产结果不是同一配置。稳态暴露 EP 通信占 18.2%，计入 warmup 与 cooldown 后只隐藏 26% 的 EP 通信，暴露 EP 总计占 38.9%。原因是该模型每个专家的计算量较少，GEMM 相对 A2A 更短，单个重叠对缺少足够计算来隐藏通信。这些结果说明重叠收益受工作负载的计算—通信比例限制。

4.3 公开 Megatron-Core 基线对比

作者另在 256-GPU 集群上，将 Tessera 与 Megatron-Core MoE v0.16.1 的公开逐模型 recipe 对照；recipe 来自 Megatron-MoE-ModelZoo（commit 1ca7da9）与 Megatron-Bridge v0.4.1，并已启用 Megatron-Core 的 EP 通信重叠。三个模型分别是：Qwen3-235B（128 个专家选 8 个，序列长度 4K）、DeepSeek-V3（dense prefix、压缩 MLA attention、multi-token prediction（MTP）和稀疏 MoE，256 个专家选 8 个，序列长度 4K）和 Nemotron-3 Super（混合 Mamba/Attention、latent MoE 与 MTP，512 个专家选 22 个，序列长度 8K）。

三个模型在 Internal Megatron / Megatron-Core MoE / Tessera 三种配置下的 MFU 依次为：Qwen3-235B 31.6% / 32.4% / 40.1%，DeepSeek-V3 27.2% / 33.4% / 33.7%，Nemotron-3 Super 24.6% / 26.3% / 27.7%。相对内部基线，Tessera 的 MFU 分别达到 1.27×、1.24× 和 1.13×；相对公开 recipe，Qwen3-235B 的 MFU 达到 1.24×，DeepSeek-V3 与 Nemotron-3 Super 分别高 0.3 和 1.4 个百分点。

作者将收益归因于三部分：隐藏暴露的 EP 通信、降低阶段负载不均，以及让 DBO 把延后的 Wgrad 与 PP send/receive 重叠。在 Qwen3-235B 上，相对内部基线，暴露 EP 通信减少约 75%，PP 等待减少约 90%；在 DeepSeek-V3 上，两套系统都隐藏了 70% 以上的 EP 通信，公开配置的 MFU 相差 0.3 个百分点；在 Nemotron-3 Super 上，Megatron-Core 的手工重叠实现最多支持一个 MTP 层，Tessera 将暴露 EP 通信降低 40%、bubble 降低 30%。

256-GPU 集群上的三种方案 MFU（Figure 11: MFU comparison among Internal Megatron, Megatron-Core MoE, and Tessera on a 256-GPU cluster. Tessera remains competitive with publicly available Megatron-Core MoE recipes on the non-Qwen workloads while consistently improving over the internal Megatron baseline across all three models.）

4.4 共优化收益与调度精度

为了单独验证分区与重叠调度是否需要联合优化，论文在 Qwen3-Next-80B（128 GPU）和 Qwen3-Next-M（256 GPU）上使用相同的交错式 1F1B 设置：每 GPU 一个 microbatch，PP=4、interleave size=2、EP=32；为支持 64K 序列还启用 context parallelism（CP，沿序列维度切分）。测试使用均匀分配 token 的 mock router 并关闭 DBO，以排除动态路由影响。对照包含 Megatron-LM 原生均匀分区、按串行耗时平衡的 Partition A，以及 Tessera 按重叠后代价平衡的 Partition B，各自再比较启用与关闭细粒度重叠调度的结果。以 Megatron-LM 原生均匀分区为基线，Qwen3-Next-80B 上 Partition A/B 在无重叠时的吞吐分别提高 13.0%/12.0%，启用重叠后提高 30.4%/39.1%；Qwen3-Next-M 上对应为 21.8%/20.6% 和 27.6%/34.1%。

重叠调度器评估使用序列长度 4K 的 Qwen3-Next-M。EP=8 和 EP=32 分别产生 536 和 690 个候选调度实例。与 CBC 求解的 ILP 参考相比，Tessera 的启发式事件调度在解析 makespan 上分别距 ILP 0.12% 和 1.19%，在实测重叠后代价上分别距 ILP 0.76% 和 1.07%。调度器单个实例在一分钟内完成；ILP 采用每实例 300 秒预算，全部实例求解可能需要数小时至数天。

4.5 DBO 运行收益与规划开销

DBO 的独立消融使用 Qwen3-Next-M、256 张 GPU、序列长度 4K，并把每 GPU 的 movable-task pool 上限设为 8。Baseline Partition 按串行 FLOPs 平衡；Overlap-Aware Partition 由 Tessera 按实测重叠代价选择。always-keep 配置执行完整的 DBO 监控、槽位估算与注入判断，但不实际延后任务，用于估算运行时开销。

DBO 分别让 Baseline 与 Overlap-Aware 的迭代时间降低 5.4% 和 4.4%；always-keep 相对 static 约增加 1% 时间。延后 Wgrad 会延长关联 activation 和 gradient tensor 的存活时间，因此启用 DBO 后每 GPU 峰值显存增加 2–4 个百分点。受显存限制的负载曾因过度填充而发生 out-of-memory（OOM）；实际部署通过限制每 GPU pool 容量控制这项代价。另一条独立的 6,144-GPU Qwen3-L 运行中，DBO 单独减少 641 ms bubble，吞吐提高 3.4%。

除了 DBO 的运行时收益与显存代价，静态计划还需要离线 profiling 和 MILP 求解。规划开销在 64-GPU 参考组上测量，目标配置为 8,192 GPU、PP=8 的 2 或 4 个 chunk/rank，序列长度从 4K 到 128K。配置名中的 M/L 分别指 Qwen3-Next-M/L，C2/C4 表示每个流水线 rank 的 chunk 数。不同序列长度与设置共产生数百种不同重叠对：PP8-C4 下为 237–327 对，PP8-C2 下为 575–637 对。trillion-scale、128K 序列、PP8-C2 的 profiling 最多约 3,050 秒，仍少于一小时。经按基线代价剪枝后，MILP 在 64 核服务器上 0.34–4.22 秒求解完成：

静态规划使用实测重叠后代价，是因为解析调度估计与硬件运行平均相差约 5%。论文观察到 EP 通信 kernel 会占用约 20 个 SM（streaming multiprocessor）；与 Attention 或 MoE-MLP 重叠时，可造成 10%–20% 的稳定减速。较低成本的 primitive-level profiling 在尾部重叠对上误差仍可达 15%，因此生产默认采用更准确的 chunk-pair profiling。profiling 的重复模型结构使其开销在万亿参数模型上仍低于一小时。

Tessera 只改变任务在设备时间线上的执行位置与顺序，不改计算图、算子语义或归约顺序。确定性模式下，万亿参数 Qwen3-Next 的启用与未启用运行产生逐位相同的 loss 轨迹。
