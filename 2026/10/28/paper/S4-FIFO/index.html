S4-FIFO：用预训练模型为 S3-FIFO 选参

论文：Learning-Augmented Heuristics: Simple, yet Smart, Robust and Interpretable Cache Eviction，Haocheng Xia、William Nixon、Bintang Dwi Marthen、Pranav Bhandari、Juncheng Yang，20th USENIX Symposium on Operating Systems Design and Implementation（OSDI 2026）。论文：USENIX presentation。

TLDR： 静态缓存启发式用固定参数处理所有 workload；论文发现，S3-FIFO 的固定配置在尾部 trace 上仍可通过选参降低 miss ratio。object-level（逐对象）模型可能优化 reuse distance（预测对象再次访问远近的指标）等代理目标，逐 miss 更新则会追随高方差请求信号，而 object-level 推理还可能进入关键路径。论文提出 Learning-Augmented Heuristics（LAH），离线用 4,140 条记录对象请求顺序的生产 workload trace 训练单个模型，部署时由 control plane 异步为参数化的 S3-FIFO 选参，data plane 继续执行简单的 FIFO 启发式。在 1,035 条留出 trace 上，cache 容量为各 trace working set（对象集合）的 10% 时，S4-FIFO 相对 FIFO 的平均 miss-ratio reduction 比 S3-FIFO 高 26%、比 3L-Cache 高 8%；按各算法各自最差的 trace 计算，大 cache 下 S4-FIFO 的 miss ratio 比 FIFO 高 0.8%，3L-Cache 高 8.8%。

一、背景：cache eviction 算法的分类

缓存空间有限，cache eviction 决定空间不足时移除哪些对象。生产系统主要采用 LRU、2Q、S3-FIFO、SIEVE 等静态启发式，因为它们规则简单、易部署。另一类 smart cache 会根据工作负载调整策略或学习淘汰决策，例如 ARC、LeCaR、LRB、LHD、GL-Cache 和 3L-Cache。

论文按学习粒度和预测频率将这些算法放进一个二维分类：学习粒度分为 object-level 和 cache-level（面向整张缓存），预测频率分为每次 miss 都预测（every-miss）和 periodic（定期预测）。已有算法占据其中三个象限，缺少 periodic、cache-level 的组合：定期观察整张缓存的状态，再选择一组全局参数。

算法分类及 periodic cache-level learning 所在位置（Figure 1: A classification of eviction algorithms (Section 2.2) indicates that periodic cache-level learning is highly effective, yet it has not been explored. We bridge this gap with learning-augmented heuristics, exemplified by a new algorithm, S4-FIFO, which achieves both high efficiency and strong robustness.）

二、现状：object-level 学习的目标错位与代价

许多学习型缓存用 object-level 方法预测 reuse distance、utility 或淘汰概率，但这些预测指标不是缓存真正要优化的目标。真正的目标是 miss ratio。object-level 模型即使把预测误差降得更低，也可能选错淘汰对象，最终增加 miss；论文用两个对象的 reuse-distance 预测说明了这种目标错位。

object-level 预测误差较低不保证 miss 更少（Figure 2: Object-level learning has an objective mismatch issue. A smaller loss on object-level metrics, e.g., reuse distance, does not guarantee fewer cache misses.）

逐 miss 更新还会追随短时间尺度的波动。作者在 CloudPhysics trace 上观察到，miss ratio 的测量窗口越短，波动越大；另一项逐 miss 自适应比较使用 106 条 CloudPhysics trace，LeCaR 优于给所有 trace 使用同一组静态参数，却明显不如为每条 trace 离线挑选最佳静态参数。这说明选对参数，比每次 miss 都改参数更重要。主评测数据表在过滤少于 100,000 个对象的 trace 后列出 104 条 CloudPhysics trace；论文没有解释这两个计数的差异。

细时间窗口下 miss ratio 波动更大，逐 miss 自适应也不及为 trace 选对静态参数（Figure 3: (a) Cache metrics, such as miss ratio, exhibit greater variance at finer time granularity. (b) Choosing the correct parameters can outperform LeCaR’s per-miss adaptivity.）

object-level learning 还要为对象保存特征，并可能在每次 miss 的关键路径上运行推理。论文举例，LRB 为每个对象增加超过 200 bytes 的特征数据。逐 miss 的反馈也有延迟：对象被淘汰后，只有再次访问时才会产生 miss，因此反馈可能晚于淘汰决策；参数改变也要经过后续请求才能影响 miss ratio。periodic prediction 可以避开逐请求推理，但 GL-Cache 等 object-level 方案会复用对象分组的旧预测，预测容易随工作负载变化而过期。cache-level 学习能直接围绕 miss ratio 调整少量全局参数，但参数更新的频率和幅度仍需要设计。

三、问题：periodic cache-level 选参

作者的生产 trace 分析显示，S3-FIFO 的固定配置在尾部 trace 上仍可通过选参降低 miss ratio。论文希望保留 FIFO 启发式的简单性和吞吐，同时让系统从整张缓存的状态中学习一组能降低 miss ratio 的参数。

论文提出 Learning-Augmented Heuristics（LAH）：在 cache-level 学习全局配置，并以 periodic prediction 避免追随每次请求的噪声。训练目标直接关联 miss ratio，鲁棒性代价以 FIFO 为锚点；模型只读取具有缓存语义的聚合特征，输出的是 queue 大小和晋升阈值等可理解的配置。

四、方案：LAH 的离线训练与异步参数选择

LAH 将模型推理移出请求处理路径。预训练阶段先在训练 trace 上搜索每条 trace 的较优参数，再用默认配置运行缓存、收集 cache-level 特征，以特征和参数标签训练一个可复用模型。部署时，缓存收集一段工作负载特征，control plane 异步运行模型并选择参数；data plane 继续由确定性的静态启发式处理读写。训练离线完成，部署时不必为每条新 trace 重新训练模型。

LAH 的离线训练与在线运行流程（Figure 4: Illustration of learning-augmented heuristics. (1) Offline pretraining (left): A foundation model is trained on a massive corpus of trace features and optimal parameter labels to learn universal caching rules. (2) Online operation (right): The system decouples the critical data path from the control path. The data path collects lightweight workload-level features, while the control path asynchronously queries the pre-trained model to adapt the cache parameters to the current workload trace.）

4.1 S4-FIFO 的结构与参数配置

S3-FIFO 有 small queue、main queue 和只保存元数据的 ghost queue。small queue 过滤只访问一次的对象，main queue 保留更热门的对象，ghost queue 记录从 small queue 淘汰的对象，以便识别再次访问。S3-FIFO 为缓存对象维护 2-bit 饱和频率计数器，并用计数阈值决定对象是否晋升到 main queue。

S4-FIFO 保留三条物理 FIFO queue，增加一段由参数控制的虚拟 skip 区域，并公开五个可学习参数：small queue 容量占比、ghost queue 容量、small 到 main 的晋升阈值、ghost 到 main 的晋升阈值，以及 small queue 前段跳过频率计数的比例。skip 区域可过滤连续突发的一次性对象，不需要增加第四条物理 FIFO queue。参数候选包括 small queue 占 cache 的 5%、10%、20%、30%、50%、70% 或 90%，ghost queue 容量为 main queue 的 1、3 或 6 倍，skip 比例为 0 或 0.25；small 到 main 的晋升阈值取 1 或 2，ghost 到 main 的晋升阈值取 0 或 1。组合共 168 个，再用 greedy set cover 从中选出 18 组代表性配置供模型分类。

S4-FIFO 数据路径中的 queue 及晋升、淘汰规则（Figure 5: An illustration of the data path in S4-FIFO.）

4.2 S4-FIFO 的特征与配置选择

S4-FIFO 使用 73 维特征向量。small queue、main queue、ghost queue 各有 20-bin hit-position histogram，共 60 维，用于记录命中集中在哪些位置；其余 13 维是 hit 比例、log cache size、utility gap、filtering efficiency、ghost pressure、tail heaviness、decay rate、one-hit ratio、unique-object ratio、scan intensity 和 thrashing risk 等计数或组合特征。

训练时，系统用离线 grid search 为 trace 和 cache-size ratio 生成参数标签，并基于 FIFO 的 miss ratio 归一化不同配置之间的 regret，形成 cost-sensitive 的分类目标。推理时，模型选取期望 regret 最低的配置，因而优化 miss ratio 的同时把鲁棒性锚定在 FIFO 上。

模型是 gradient boosting decision tree（GBDT）集成，由 20 棵、最大深度为 9 的树组成，输出 18 组参数配置之一。推理代码可导出成不依赖机器学习库的实现；论文报告单次推理耗时低于 2 ms。每次读写仍是 O(1) 操作，主要新增的 data plane 工作是更新 hit-position histogram；除 S3-FIFO 原有的对象计数器外，S4-FIFO 不为每个对象增加学习特征。

4.3 运行时配置切换与队列收敛机制

运行时，S4-FIFO 先以默认配置收集特征，再异步预测一次并切换到模型选出的配置。若新配置缩小某条 queue 的目标容量，系统不立即搬移或淘汰对象；之后的淘汰优先从超过新容量的 queue 发生，直到各 queue 的实际容量达到新目标。参数切换因此不需要暂停缓存或增加请求处理路径的额外工作。论文评测每条 trace 只预测一次；作者指出实际部署可按策略触发 periodic prediction。

trace 被随机分为 4,140 条训练数据和 1,035 条评估数据。训练阶段对每条训练 trace 搜索较优配置并生成标签。评估阶段则先用默认参数运行每条 trace 的前 20% 请求以收集特征，随后异步预测一次，将预测配置用于余下 80%。为与每条 trace 只用一组参数的离线 grid-search 最优值公平比较，评测也只进行一次预测。

cache 容量设为各 trace working set 的 0.1%、1% 和 10%；论文图表主要展示最小的 0.1% 和最大的 10%，1% 结果位于两者之间。缓存 miss ratio 由 libCacheSim 计算；吞吐实验使用 Meta Cachelib 的 CacheBench。实验在 20 节点集群上完成，论文列出的配置为 32 核和 192 GB 内存；每项实验重复三次并报告均值。

鲁棒性按每个算法各自最差的 trace 衡量。大 cache（working set 的 10%）下，S4-FIFO 的 miss ratio 最多比 FIFO 高 0.8%，3L-Cache 最差时高 8.8%；小 cache（0.1%）下，S4-FIFO 的最差增幅为 0.2%。这里的最差 trace 是逐算法选出的，不保证 S4-FIFO 和 3L-Cache 对应同一条 trace。对第 10 百分位 trace，S4-FIFO 在大、小 cache 下分别将 FIFO 的 miss ratio 降低 4.2% 和 3.6%。

特征重要性分析中，small queue、main queue、ghost queue 的 histogram 合计占 75%，说明各 queue 内的命中位置分布是配置预测的主要信号。

单模型能否覆盖多种工作负载，取决于训练数据的规模和多样性。训练 trace 增加到数千条时，top-1、top-2、top-3 准确率分别接近 60%、70%、80%。

5.2 吞吐性能与模型解释

CacheBench 吞吐测试使用 CDN workload 和四种 Graph Cache workload，共五种负载，每项运行 48 个线程并报告平均吞吐。测试让 S4-FIFO 对每个请求都持续收集特征，作为特征采集开销的保守上界；即使如此，它的吞吐仍与 Cachelib 中高度优化的启发式实现相近。比较对象包括 LRU、S3-FIFO、TinyLFU 和 LRU2Q；其中 LRU2Q 是移除了 ghost queue 的修改版 2Q。另在 libCacheSim 中，3L-Cache 平均比 S4-FIFO 慢 17.3 倍，最慢达到 274 倍。

Cachelib 中 Set 与 Get 的吞吐测试（Figure 8: Set and Get throughput evaluated in Cachelib.）

S4-FIFO 的运行时参数由 GBDT 选择，LLM 不参与请求处理。作者把 LLM 作为语义可解释性的代理评估，做了两项实验：第一项把 workload 特征和模型选出的 S4-FIFO 配置交给 LLM，让它解释这些参数为何适合该工作负载；论文对这一项作定性报告，没有给出单独的准确率。第二项提供 workload 特征和 miss ratio 明显不同的两组配置，让 LLM 判断哪组更好。每种 cache-size 设置抽取 100 条 trace，第二项任务在小、大 cache 上分别达到 83% 和 86% 的准确率。论文指出，配置选择准确率不能证明所学策略正确；作者将两项实验视为特征和参数具有语义、外部模型能够据此推理的证据。当前 20 页会议论文 PDF 引用了 Appendix A.2，但未附该附录，因此无法从这份文件确认所用 LLM 的具体名称或提示词。
