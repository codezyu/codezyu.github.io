论文：Xerxes: Extensive Exploration of Scalable Hardware Systems with CXL-Based Simulation Framework，Yuda An、Shushu Yi、Bo Mao、Qiao Li、Mingzhe Zhang、Diyu Zhou、Ke Zhou、Nong Xiao、Guangyu Sun、Yingwei Luo、Jie Zhang（通讯作者），FAST ’26（24th USENIX Conference on File and Storage Technologies，2026）。作者及单位：Yuda An、Shushu Yi、Diyu Zhou、Guangyu Sun、Yingwei Luo、Jie Zhang来自北京大学；Bo Mao来自厦门大学；Qiao Li来自穆罕默德·本·扎耶德人工智能大学（MBZUAI）；Mingzhe Zhang来自中国科学院信息工程研究所；Ke Zhou来自华中科技大学；Nong Xiao来自中山大学。代码：GitHub/chaseLab-PKU/Xerxes。

TLDR： Xerxes 以图结构互联层和对等设备层模拟 CXL 3.1，覆盖端口路由、设备管理一致性和全双工传输。CXL 2.0 真机校准带宽误差为 0.1%–10%；结果显示树形拓扑限制吞吐，设备侧替换策略与读写混合也会影响性能。

一、背景：CXL 协议与拓扑演进

1.1 CXL 子协议与交换结构

Compute Express Link（CXL）基于 PCI Express（PCIe）的物理和电气基础设施，为主机 CPU、加速器和内存设备提供缓存一致性互联。协议包含三个子协议：CXL.io 提供 I/O 和配置能力，所有 CXL 设备都支持；CXL.cache 让 type-1、type-2 设备以一致性方式访问主机内存；CXL.mem 将设备内存映射进主机的一致性物理地址空间，支持 type-2、type-3 设备通过 load/store 按字节访问。根复合体（Root Complex）管理主机侧的 CXL 功能。

CXL 2.0 交换机以虚拟 CXL 交换机（Virtual CXL Switch，VCS）组织端口。VCS 的上行端口（USP）经虚拟 PCI-to-PCI 桥（vPPB）连接根端口，下行端口（DSP）连接 CXL 或传统 PCIe 设备；多 VCS 模式还能动态绑定 vPPB，将一个物理设备池化为多个逻辑设备。两种模式都沿用 PCIe 交换机的层级转发，系统仍以树形拓扑为主。

1.2 DMC 与 PBR 的协议扩展

树形互联会让不同分支间的流量汇聚到根部，也不利于设备直接通信；由主机集中管理一致性的方式，也难以扩展到大规模对等设备系统。CXL 3.0 及后续版本引入设备管理一致性（Device-Managed Coherence，DMC）和基于端口的路由（Port-Based Routing，PBR），以支持设备间一致性通信和非树形互联网络。

主机管理的设备内存（Host-Managed Device Memory，HDM）有不同的一致性管理模式：HDM-H（Host-Managed）由主机一致性引擎管理；设备管理反向无效化（Device-Managed with Back-Invalidate，HDM-DB）是 DMC 的主要实现，由设备侧一致性代理（Device Coherency Agent，DCOH）负责管理。HDM-D（Device Coherent）则为使用 CXL.cache 管理一致性的旧设备保留兼容路径。当对等设备请求某条缓存行的独占访问，而 DCOH 记录了其他对等设备持有该行时，DCOH 经 CXL.mem 专用通道向这些共享者或所有者发送反向无效化 snoop（Back-Invalidate Snoop，BISnp）。接收方无效化本地副本后返回反向无效化响应（Back-Invalidate Response，BIRsp）；若缓存行为脏数据，响应还要带回最新数据。DCOH 收齐应答后才把所有权授予请求者，因此设备可以不经主机直接进行一致性数据共享。HDM-DB 设备需要运行在 PCIe 6.0 物理层上，每条物理通道（lane）的速率为 64 GT/s。

PBR 改变了交换机的转发方式：交换机根据源、目的端口 ID 查询内部路由表，不再强制报文沿上行端口和下行端口构成的树路径转发。互联网络中连接主机或设备的边缘端口使用 12 位端口 ID，单系统最多支持 4096 个端点，因此可以构造 mesh（网格）、spine-leaf（脊叶）等非树形拓扑，缩短设备间的通信路径。

二、现状：现有模拟器的能力缺口

2.1 NUMA 仿真的协议与规模限制

由于当时缺少支持 CXL 3.x 完整特性的硬件，研究常用非均匀内存访问（Non-Uniform Memory Access，NUMA）远端节点模拟 CXL 内存。它只能近似远端访问延迟：Intel Ultra Path Interconnect（UPI）与 CXL 设备在协议层存在差异，CXL 3.x 的 PBR、DMC 等特性会进一步扩大这种错配。NUMA 仿真还受物理规模限制：CPU socket 数量有限，无法模拟最多 4096 个端点的互联网络。

2.2 传统架构与网络模拟器的建模缺口

gem5、GPGPUSim 等计算中心模拟器围绕主机和分层内存系统设计，缺少灵活的互联网络层；其集中式一致性控制也不适用于由设备自治管理的 DMC。以 gem5 为例，原生外设支持偏旧，缺少高速 PCIe 模型；加入会主动发起一致性请求的 CXL 设备，需要较大范围地修改模拟器。

BookSim、Garnet 等网络中心模拟器可以表示复杂拓扑和路由，但模拟的是通用报文，不跟踪内存请求的状态化协议交互。两类模拟器都没有同时提供互联网络感知能力和分布式一致性设备模型。

2.3 行为级 CXL 模型的预测边界

MESS、CXLMemSim 等 CXL 专用模拟器把复杂互联抽象为延迟–带宽（Lat-BW）曲线，再将预先测得的曲线作为输入，在应用执行期间注入延迟。这种行为级模型适合评估已知设备对应用的影响，但不能从组件机制推演新设备或新拓扑的性能。PBR 多路径路由带来的变化、DMC snoop 报文在互联中的延迟，都取决于底层交互，无法由固定曲线预测。

三、优化点：兼顾互联灵活性与设备一致性

现有方法缺少两项能力的联合建模：一是表示 PBR 支持的任意拓扑，二是模拟 DMC 所需的设备侧一致性管理。Xerxes 从零构建系统级框架，目标是在同一模型中覆盖这两类机制，并保留集成既有模拟器的能力。设计遵循三项原则：

  1. 模块化。 将互联网络与设备功能逻辑解耦，使物理传输层和端点协议可以分别开发、验证，也便于接入不同设备模型。
  2. 图结构连接。 按图而非树构建互联，原生支持 PBR 所需的任意非树形拓扑。
  3. 对等设备模型。 将主机、加速器和内存设备都建模为主动节点。DMC 要求设备主动接收 snoop、独立维护一致性状态，因此不能把设备仅当作主机请求的被动应答者。

四、方案：互联层与设备层协同建模

4.1 互联层：全双工 bus 与 PBR 交换机

互联层在初始化时把系统拓扑构造成图，并向组件提供基于最短路径的默认路由。普通端点可直接使用该路由；交换机等复杂组件也能查询拓扑图，实现自定义路由策略。

bus（总线）模拟 CXL 3.1 所采用的 PCIe 6.0 物理层。它记录两个方向同时传输的状态，并为每个方向分配完整带宽，以此表示全双工传输；带宽、延迟、半双工（同一时刻仅沿一个方向传输）模式和周转开销均可配置。交换机根据互联层提供的路由信息建立路由表，收包后查表并转发到目标端口。两者协同后，Xerxes 可以模拟非树形 CXL 互联网络的端到端传输。

4.2 Requester 的主动设备模型

主机和加速器等计算实体统一抽象为 Requester（请求端），由三个单元组成：请求队列通过队列深度和发射间隔控制在途请求数；地址转换单元配置请求在多个内存端点间的交错策略；缓存一致性管理单元维护本地缓存状态，并在收到 BISnp 后查找缓存行、迁移状态并应答。Requester 可生成合成流量，也可回放应用的内存访问轨迹（trace）。

4.3 设备侧 snoop filter 的一致性管理

Xerxes 用独立的全相联缓冲区（buffer）实现设备侧 snoop filter（SF），记录对等设备缓存行的一致性元数据，包括状态和所有者列表。SF 收到一致性请求时更新表项；若所有权冲突，就先向原所有者发送 BISnp，再处理新请求。

SF 表项不足时会选择 victim（待替换表项），并向对应所有者发送 BISnp。收到所有 BIRsp 后，SF 才清除表项并复用空间；若缓存行是脏数据，则将其写回对应端点。victim 选择策略可替换，便于评估不同策略对一致性流量和性能的影响。

4.4 与既有模拟器集成

Xerxes 与 gem5、DRAMsim3 和 SimpleSSD 集成，分别复用处理器、DRAM 和 SSD 模型。gem5 侧在内存控制器（MemCtrl）外增加适配层（wrapper），并通过 UpInterface、DownInterface 转换 gem5 与 Xerxes 的内存包；wrapper 复用 gem5 的事件队列，并为 CXL 互联增加额外延迟。DMC 接口使用 gem5 的 SLICC 工具，在 DCOH 发起反向无效化时调用 gem5 事件，使缓存层次中的对应缓存行失效。

DRAMsim3 按周期推进，wrapper 定期注册时钟事件；SimpleSSD 由事件驱动，wrapper 将其事件转换为 Xerxes 事件引擎可处理的格式。由此，Xerxes 可与不同粒度的端点模拟器协同工作。

五、结果：真机验证与架构探索

5.1 真机校准与端到端验证

Xerxes 的硬件校准平台为双路 Xeon Gold 6416H 服务器，每路连接 8 个 DDR5-4800 双列直插式内存模块（DIMM），单 socket 峰值带宽为 76.8 GB/s，主存共 512 GB。其中一路连接 Montage MXC（内存扩展控制器）CXL 内存扩展器，控制器支持 CXL 2.0 和 PCIe 5.0 ×16；扩展器内有 4 个 DDR5-4800 DIMM，提供 128 GB、采用 HDM-H 模式的设备内存。通往远端 socket 的线缆占用扩展器一半物理通道，因此每个 socket 可用带宽相当于 PCIe 5.0 ×8，理论值为 32 GB/s，实测可达 24 GB/s。

校准对比了远端 NUMA 节点、MESS、CXLMemSim 和 gem5-garnet。NUMA 节点配置为 4 个 DIMM，与扩展器的 DIMM 数量一致；MESS 和 CXLMemSim 使用同一 CXL 硬件实测得到的延迟–带宽输入。Xerxes 由 Requester、互联 bus 和 4 个 DRAMsim3 内存端点组成。硬件流量由 Intel Memory Latency Checker（MLC）产生；校准覆盖空载延迟、不同读写比例下的峰值带宽，以及不同请求强度下的负载延迟。模拟器延迟参数取自公开资料和既有测量：

相较 CXL 硬件，Xerxes 的带宽误差为 0.1%–10%，负载延迟–带宽曲线的平均误差为 4.3%；MESS 和 CXLMemSim 的曲线平均误差分别为 9.3% 和 16.6%。读写混合增加时，CXL 硬件和 Xerxes 的峰值带宽曲线均上升。

5.2 设计空间探索：拓扑、DMC 与全双工

拓扑实验使用 N 个 Requester 和 N 个内存设备，以 N-N 系统表示规模 2N；Requester 向所有内存端点随机发请求，各拓扑的交换机端口带宽固定。chain 和 tree 的跨交换机“桥”路径被多个 Requester 共用，系统带宽因此受单个交换机端口限制；ring 提供绕行路径，带宽可达单端口容量的 2 倍。spine-leaf 将瓶颈转移到 leaf 端口，系统带宽为单端口容量的 N/2 倍；全互联为每个 Requester 提供完整端口带宽，聚合带宽为单端口容量的 N 倍。

在等二分带宽（iso-bisection bandwidth）设置下，平均延迟随请求经历的交换机跳数增加而上升。chain 中最高跳数组的延迟是最低跳数组的 2 倍；tree 和 ring 的共享桥路径也会拥塞，而 spine-leaf 和全互联的通信路径跳数较少。

在 BTree、liblinear、Redis、Silo 和 XSBench 的内存访问轨迹上，ring 吞吐最高可达 chain 的 1.72 倍，spine-leaf 和全互联最高可达 3.63 倍。

模拟规模从 1 扩至 64 时，运行时间低于 90 秒；chain、tree、spine-leaf 的内存占用低于 200 MB。全互联的链路数随规模平方增长，因此内存占用上升更快。

论文还在 tree 拓扑下测试 BERT、PageRank 和 YCSB-F。内存端点由 1 个增至 16 个时，平均访问延迟约增至 9 倍。

DMC 的 snoop filter 实验使用偏斜访问：90% 请求落在占内存足迹 10% 的热点数据上，本地缓存容量为内存足迹的 20%，SF 容量与本地缓存相同；本地缓存过滤命中请求，未命中的请求经无限带宽 bus 到达 SF。五种 victim 策略中，LIFO（Last-In, First-Out）相较 FIFO（First-In, First-Out，先进先出）将带宽提高 5%，平均延迟降低 15%，无效化次数降低 16%。这是因为稳态下热点数据大多留在本地缓存，到达 SF 的请求以冷数据未命中为主；FIFO 和 LRU（Least Recently Used，最近最少使用）更容易无效化热点行。LFI（Least Frequently Inserted）用全局计数表记录插入次数，相较 FIFO 将无效化次数降低 15%；计数趋同时，它会周期性地无效化热点行，论文报告其性能低于 LIFO 和 MRU（Most Recently Used）。

不同 snoop filter victim 策略的性能（Figure 15: Performance of different snoop filter (SF) victim selection policies, normalized to FIFO.）

论文还评估了协议级 InvBlk 命令。SF 发出 BISnp 时可附带 InvBlk，要求所有者一次无效化连续地址上的 2–4 条缓存行。实验使用两个顺序发出请求的 Requester，各自带有本地缓存，并由设备侧 SF 管理一致性状态；SF 优先选择可连续无效化的最长表项序列，多个候选间使用 LIFO。长度为 2 时，一条 BISnp 能清除两条表项，减少后续请求等待无效化的时间，并同时降低平均延迟、提高带宽。长度超过 2 后，本地缓存访问开销和 BISnp 数据争用传输带宽抵消了收益，性能不再优于长度 2。

不同 InvBlk 长度的性能（Figure 16: Performance of different InvBlk lengths, normalized to length = 1.）

PCIe 全双工实验使用随机发请求的 Requester、带有可调报文头部开销的 bus 和 4 个内存设备，改变读写比例和头部开销；头部开销按有效载荷（payload）长度归一化。半双工 bus 的带宽基本不随读写比例变化；全双工 bus 在读写混合时可同时使用两个方向，带宽随流量均衡而上升。头部开销为零时，1:1 读写流量的带宽接近只读场景的 2 倍；头部长度达到有效载荷长度时，混合读写不再带来带宽收益。论文还定义 bus utility（总线忙碌时间占仿真时间的比例）和 transmission efficiency（有效载荷传输时间占 bus 传输时间的比例），用于区分链路利用率与有效载荷效率。

在真实内存访问轨迹上，mix degree 定义为读、写比例中的较小值；该值每增加 0.1，整体带宽约提高 9%。Silo 的全双工带宽约为单方向峰值的 1.2 倍。读写比例决定两个方向能否同时承载有效载荷，头部开销决定传输时间中有多少用于有效载荷；两者共同限定全双工带宽收益。

六、局限与后续工作

论文对 CXL 3.1 的 PBR、DMC 采用理论模型校验，真机校准使用 CXL 2.0、PCIe 5.0 扩展器；端到端评估仅覆盖 SPEC CPU2017 的 gcc 和 mcf。

论文列出 OpenCAPI、Gen-Z 和 Unified Bus（UB）等一致性互联，并以 UB 为例讨论扩展方向：在设备层加入 UB controller 和 UB memory management unit（UMMU），以 UMMU 替换设备侧 snoop filter 来支持远端内存访问；互联层则可扩展到 UB-Mesh 等拓扑。
