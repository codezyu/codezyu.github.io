DPAS：面向 SSD 的即时、精确且安全 I/O 完成

论文：DPAS: A Prompt, Accurate and Safe I/O Completion Method for SSDs，Dongjoo Seo、Jihyeon Jung、Yeohwan Yoon、Ping-Xiang Chen、Yongsoo Joo、Sung-Soo Lim、Nikil Dutt，USENIX FAST ’26（2026）。论文：USENIX PDF。

TLDR： PAS（Prompt, Accurate and Safe）依据逐条 I/O 的睡眠结果校准混合轮询时长，跟随时延变化并动态调整跟踪灵敏度，减少固定折扣与 epoch 统计造成的误差；DPAS（Dynamic PAS）再依队列深度和请求睡眠时长归零（timer failure），在经典轮询（classic polling）、PAS 与中断间切换，避免持续过载时退化为定时器忙等。4 KB 随机读中，PAS 的 CPU 使用率比 Linux hybrid polling 低 21 个百分点；CPU 与 I/O 同时干扰时，DPAS 的 Yahoo! Cloud Serving Benchmark（YCSB）A–F 操作数/秒（OPS）在 Intel Optane DC P5800X、Samsung 983 ZET、SK hynix P41 Gold 上平均分别高 9%、7%、5%。

一、背景：中断、轮询与混合轮询

传统存储 I/O 完成依赖中断。SSD 延迟降到微秒级后，上下文切换、中断处理、缓存污染和 CPU 电源状态转换的隐藏成本变得突出。经典轮询（classic polling，CP）消除了这些开销，能让应用更早恢复执行，但会独占 CPU；在 CPU 竞争下，CPU 资源被轮询占用会使整体性能恶化。

混合轮询（hybrid polling）把一条 I/O 分成睡眠段和轮询段：提交 I/O 后先睡眠估计时长，醒来再轮询完成队列。它的收益取决于唤醒时刻是否贴近真实完成时刻。睡眠不足（undersleeping）会留下较长的轮询时间，CPU 开销偏高；过睡（oversleeping）会直接增加应用感知时延。论文因此优先避免过睡，因为睡眠过久会抵消轮询带来的性能收益。

中断、经典轮询和混合轮询的 I/O 完成方式（Figure 1: Comparison of I/O completion detection methods. CS (context switching) includes times spent on context switches and executing interrupt handler functions.）

二、现状：epoch 统计的误差来源

Linux hybrid polling（LHP）按读写方向和 I/O 大小维护 16 个 bucket（8 个大小段），每 100 ms 更新一次统计；下一条 I/O 的睡眠时长取上一 epoch 平均 I/O 时延的一半，即 1/2×mean。50% 的折扣能让 CPU 使用率较 CP 约减半，但有三类问题：

  • Promptness：统计按 epoch 更新，I/O 行为突变后要等到下一个 epoch 才反映。
  • Accuracy：稳定的低时延负载会被固定 50% 折扣提前唤醒，浪费 CPU。
  • Safety：时延变化剧烈时，50% 折扣仍可能不够，造成过睡。

后续方案也未同时解决这些问题。HyPI 用离线 profile 按 I/O 大小设置衰减率，无法响应运行时变化；EHP 改用上一 epoch 的最小 I/O 时延，并把 epoch 缩短到 10 ms，虽减少了衰减余量，但单个提前完成的 I/O 就可能让后续睡眠过短。更关键的是，LHP、HyPI 和 EHP 只看测得的总 I/O 时延，无法区分设备变慢与操作系统（OS）调度延迟或预测误差造成的过睡。作者把这种错误反馈称为 “latency shelving”：软件延迟被误判为设备时延，后续睡眠时长因而持续增加。

不同睡眠时长估计方法与实际 I/O 时延（Figure 2: Comparison of sleep-estimation methods. The trace shows write I/O latencies from a ULL SSD [8] while running the YCSB benchmarks [14]. The two hybrid polling methods, 1/2 · mean and 3/4 · mean, use attenuation rates of 0.5 and 0.75; the min uses the minimum I/O time from the last epoch.）

已有的完成方式切换机制依赖预先定义的应用类别、I/O 大小或 CPU 使用率阈值，缺少识别瞬时调度延迟的手段。

三、优化目标：及时估时与运行时适应

混合轮询需要及时跟随 I/O 时延变化，同时区分设备处理时间与软件导致的过睡；完成方式还要能按运行时竞争调整，避免定时器忙等，并保留低竞争时轮询的吞吐优势。

四、方案：PAS 反馈与 DPAS 模式切换

4.1 PAS 的下包络跟踪与睡眠调整

PAS（Prompt, Accurate and Safe）不直接把测得的 I/O 时延当作下一步要追踪的目标，而是跟踪 I/O 时延的下包络（lower envelope），即波动时延序列中较低的边界。它记录最近两次睡眠结果：唤醒后 I/O 已完成记为 OVER，仍未完成记为 UNDER。修改后的内核 poll 函数会返回这一结果，不需要 SSD 额外上报。设备处理时间变长会逐渐推动睡眠时长增加；若结果表明发生过睡，PAS 则会立即缩短睡眠。

PAS 沿用 LHP 的 bucket 结构，在每个 bucket 内维护当前请求睡眠时长 duration、调整因子 adjust，以及增量参数 UP 和 DN。每次收到新的睡眠结果后，PAS 更新 adjust，再将它乘以当前 duration 得到下一次请求时长。

PAS 的工作流程和伪代码（Figure 3: The workflow and pseudocode of PAS）

初始请求睡眠时长 D_MIN 为 0.1 µs，PAS 从短睡眠逐步逼近实际时延。PAS-Sim（基于表格的 PAS 模拟器）在 YCSB 实测时延序列上扫描参数，选择基线 (UP, DN) = (0.01, 0.1)：过睡时更果断地缩短睡眠，睡眠不足时较保守地延长，以避免严重过睡。

PAS 根据最近两次睡眠结果调整时长（Figure 4: An example of adjusting sleep duration with two sleep results）

PAS 与其他睡眠估计方法的时长比较（Figure 5: Comparison of sleep-duration values for PAS and the alternative methods described in Section 2.）

PAS-Sim 固定 UP 为 0.01，并将 DN/UP 比值从 1 调到 20。比值从 1 增至 4 时，归一化过睡时间 T_over 快速下降；超过 4 后变化很小，而归一化睡眠不足时间 T_under 仍随比值增加。

DN/UP 比值对过睡与睡眠不足的影响（Figure 6: Effect of varying the DN/UP ratio. UP is fixed at 0.01, while DN is swept from 1×UP to 20×UP.）

4.2 PAS 灵敏度的自适应调节

固定灵敏度不适用于 I/O 行为变化的不同阶段。PAS 在连续两次结果相同时，将 UP 和 DN 乘以 1 + HEATUP（同向结果时提高灵敏度）；连续两次结果不同时，则乘以 1 - COOLDN（结果切换时降低灵敏度）。实验选择 (HEATUP, COOLDN) = (0.05, 0.1)，固定 UP:DN = 1:10，并把 UP 限制在 [0.001, 0.01]。作者在后续实验中沿用这组参数，不逐设备调优。

不同 HEATUP 值下的动态灵敏度测试（Figure 8: Dynamic sensitivity tests with varying HEATUP values (COOLDN fixed at 0.1).）

4.3 并发 I/O 的 per-core 状态

多条 I/O 在途时，按设备共享一套 PAS 状态会产生三个问题：旧睡眠结果被新 I/O 重复使用，可能使睡眠时长指数增长；并发完成的 I/O 会相互覆盖结果，导致跨越方向变化时丢失 (UNDER, OVER) 或 (OVER, UNDER)；共享控制变量还需要加锁，串行化 I/O 更新。PAS 因此改用 per-core 状态，每个 CPU 各自维护 bucket、睡眠结果和调整因子。同一 CPU 上有多线程时，同一睡眠时长下只有最先完成的 I/O 提交睡眠结果；看到新结果的第一个 I/O 更新睡眠时长，其余 I/O 复用更新后的值。

per-device 和 per-core PAS 对并发 I/O 的处理（Figure 9: Per-device and per-core PAS modes with (UP, DN) = (0.05, 0.1). The number inside each I/O denotes its adjust value. (a) In per-device mode, the response to concurrent I/Os is sluggish. (b) In per-core mode, PAS variables are kept per CPU core, eliminating the issue. (c) Multiple threads share a CPU; arrows depict the flow of sleep-result submission and duration updates.）

扩展 PAS 的动态灵敏度与并发 I/O 支持（Figure 7: Extended PAS with dynamic sensitivity and concurrent I/O support）

实现位于 Linux multi-queue block layer。每核 16 个 PAS bucket 占 592 B，DPAS 切换逻辑占 104 B；此外，每核另有 100 B 用于 PAS/DPAS 全局变量。实现修改了 9 个源文件，新增约 1,224 行、删除 30 行，不含 trace 代码。

4.4 DPAS 的运行时模式切换

PAS 仍受混合轮询本身的限制：高精度定时器和间接任务切换会增加 I/O 时延。Optane 上，固定睡眠 1 µs、保证不发生过睡的 LHP 达到每秒 129 千次 I/O（KIOPS），低于 CP 的 134 KIOPS。CPU 过载时，调度器可能无法按时唤醒 PAS，使实际睡眠长于请求值；若线程醒来时 I/O 已完成，poll 函数才会返回 OVER，PAS 随即缩短请求睡眠时长。若过载持续，请求睡眠时长降到 0，进入 timer failure 状态，随后退化为反复调用定时器的高开销忙等，可能不如 LHP 或中断。

DPAS 把 per-core PAS 扩展为四种模式：PAS normal（正常 PAS）、PAS overloaded（过载 PAS）、经典轮询（classic polling，CP）和中断（interrupt）。它根据队列深度（queue depth，QD）与 timer failure 切换：

  • 在 PAS normal 模式，DPAS 用 NPAS = 100 条 I/O 采样并计算平均 QD。若 QD 为 1，表示主要由单线程发出 I/O，DPAS 切到 CP；执行 NCP = 1000 条后回到 PAS normal，以利用低竞争时 CP 的吞吐优势。
  • 若 PAS normal 期间检测到 timer failure，DPAS 进入 PAS overloaded 模式，再观察 NPAS 条 I/O。只有 QD 回到 1，才回到 PAS normal。
  • 若 PAS overloaded 模式下 QD > θ，DPAS 切到 interrupt 模式，执行 NINT = 10000 条中断 I/O 后回到 PAS overloaded，等待过载结束。

当 1 < QD ≤ θ 时，DPAS 留在 PAS overloaded 模式继续观察；因此在 3D XPoint 的 θ = 3 设定下，QD 为 2 或 3 时不会切到中断。

DPAS 的模式转换（Figure 10: Mode transition diagram of DPAS）

NAND SSD 的阈值取 θ = 1，因此更早切到中断；3D XPoint SSD 取 θ = 3，会在 PAS overloaded 模式停留更久。NINT = 10000 用来减少短窗口引起的模式抖动：32 线程竞争 P41 时，NINT = 100 的吞吐只有中断方法的 0.84 倍，NINT = 10000 时提高到 0.97 倍。

DPAS 模式切换参数的敏感度（Figure 12: Sensitivity of DPAS parameters (NCP, NINT) regarding normalized IOPS and CPU usage (4 KB random reads on four CPUs). (a) Increasing NCP from 100 to 10,000 under no CPU contention (4T) on Optane. (b) Increasing NINT from 100 to 100,000 under heavy CPU contention (32T) on P41.）

每个 CPU 使用两条设备队列，分别承载轮询 I/O 和中断 I/O。CPU 数远多于设备队列时，多个 CPU 可能共享中断队列；论文提出可让两种 I/O 共用单队列，或动态调整 poll/interrupt 队列映射来缓解。

五、结果：不同负载下的性能与代价

5.1 微基准与 I/O trace

平台为 Intel Xeon Gold 6230（20 核，2.10 GHz）、192 GB DDR4，关闭超线程。SSD 包括 Intel Optane DC P5800X 400 GB（3D XPoint）、Samsung 983 ZET 480 GB（SLC-based Z-NAND；SLC 指 single-level cell，Z-NAND SSD 简称 ZSSD）和 SK hynix P41 Gold 1 TB（TLC NAND；TLC 指 triple-level cell，简称 P41）。对比方法为中断（interrupts，INT）、CP、LHP、EHP、PAS 和 DPAS，每组实验平均 5 次。FIO（Flexible I/O Tester）每次运行 10 秒，在 XFS 文件系统上使用 direct I/O（绕过页缓存的直接 I/O）；FIO 的 pvsync2 I/O engine 通过 hipri 参数启用轮询完成。

4 KB 随机读测试中，Optane 上 CP 的读吞吐最高比 INT 高 30%，写吞吐高 27%。设备饱和前，CP 和 DPAS 的吞吐高于 LHP、EHP 和 PAS；此时 DPAS 主要处于 CP 模式，CPU 使用率超过 90%。LHP 在各线程规模下消耗约一半 CPU；EHP 和 PAS 随时延调整 CPU 使用率。PAS 的 CPU 使用率在混合轮询方法中最低，平均比 LHP 少 21 个百分点。

4 KB 随机读的线程扩展与 CPU 使用（Figure 11: Thread scalability (4 KB I/O size, 1 thread per CPU). The NIOPS y-axes are scaled differently for legibility.）

128 KB 读时，三块 SSD 上的 EHP 均未比 INT 提高 I/O 操作数/秒（I/O operations per second，IOPS）；P41 上 DPAS 的 128 KB 读 IOPS 比 INT 低约 1%。

不同读请求大小下的 IOPS 与 CPU 使用（Figure 13: Random read tests with 1 thread (size: 8–128 KB). The NIOPS y-axes are scaled differently for legibility.）

真实 I/O trace 回放使用 SNIA IOTTA 的 Baleen（以大 I/O 为主）、Systor’17 VDI trace 和 Slacker 应用启动 trace；Systor 和 Slacker 含有较多小 I/O。Baleen 以大 I/O 为主，中断与其他方法的 IOPS 差距在所有 SSD 上都很小；Systor 和 Slacker 中小 I/O 较多，能体现轮询收益。LHP 和 PAS 通常比 EHP 的 IOPS 高，PAS 的 CPU 使用率低于 LHP。CP 在多数测试中取得最高 IOPS，但在 P41 上例外；DPAS 在各测试中接近最优，并在 P41 上超过 CP。P41 上 DPAS 的 CPU 使用率也较高，与其较多采用 CP 模式相符。

三种 I/O trace 回放结果（Figure 14: Trace replay results for three workloads (error bars: standard deviation).）

5.2 YCSB 下的资源竞争与设备适应

宏基准在 RocksDB 上运行 YCSB A–F，并以 pvsync2 替换 POSIX I/O 接口来启用轮询。线程扩展实验中，Optane 上 8 线程以内，LHP、EHP、PAS 的 OPS 比 INT 高 5–8%；ZSSD 上 DPAS 在 1–16 线程时高于 INT；P41 上混合轮询在 1–20 线程的各个测试点均高于 INT。

YCSB 线程扩展结果（Figure 15: Thread scalability. The number of threads equals the number of CPUs. The average across YCSB A–F is shown. For legibility, the NOPS y-axes start at 90%.）

将线程限制在 4 个 CPU 时，ZSSD 和 P41 上 16–32 线程的 CP OPS 约为 INT 的 70%。PAS 的 OPS 高于 INT 的范围是：Optane 和 ZSSD 上 2–8 线程，P41 上 2–4 线程；在 ZSSD 和 P41 上，PAS 的 OPS 在 16–32 线程低于 INT。DPAS 在 2–4 线程时保持 CP 模式并取得最高 OPS；检测到 timer failure 后，它切换到中断或 PAS overloaded 模式，以抑制过载造成的退化。

CPU 竞争下的 YCSB 结果（Figure 16: Tests under CPU contention (4 CPUs). For ZSSD and P41, CP’s OPS values are flattened for legibility.）

模式分解实验展示了切换效果：YCSB-C、Optane、8 线程时，DPAS 留在 PAS overloaded 模式而不切中断，OPS 比 INT 高 12.3%；YCSB-B、ZSSD、4 线程时，约 2% 的 I/O 使用中断，DPAS 的 OPS 比 INT 高 10.3%，CP 只高 0.3%；YCSB-A、P41、8 线程时，多核发生 timer failure，多数核切到中断，DPAS 总 OPS 比 INT 低 2.8%，而 PAS 低 9.3%。

DPAS 的 I/O 模式分布（Figure 17: Breakdown of I/O modes in DPAS (4 CPUs).）

在 CPU 与 I/O 同时干扰的受控实验中，4 条 YCSB 线程运行在 CPU0–3，4 个 I/O pulse generator 运行在 CPU4–7；每个 generator 持续发出每秒 1,000 次 I/O（IOPS）的 128 KB 随机读，pulse interval 为 40–640 ms，总流量约 500 MB/s。DPAS 在 Optane、ZSSD、P41 上的平均 OPS 分别比 INT 高 9%、7%、5%。

I/O 干扰下的 YCSB 性能（Figure 18: I/O interference. Eight CPUs are used to run four YCSB threads and four I/O generator threads (128 KB reads at 1,000 IOPS each). The NOPS y-axes start from 70%.）

CPU 与 I/O 竞争下的吞吐、CPU 使用率和模式分布（Figure 21: Tests under varying CPU and I/O contention. Four CPUs were used to run 4 YCSB threads and 4 I/O generator threads, configured identically to Figure 18 (error bars: standard deviation).）

时延分解显示，在 Optane 的 YCSB-B 测试中，80 ms I/O pulse 下 CP 的 READ 与 UPDATE 平均时延都低于 INT；ZSSD 上，CP 的 UPDATE 平均时延高于 INT，P99.99 时延和最大时延分别是 INT 的 17 倍和 30 倍。I/O 干扰期间，DPAS 最多约 90% 的 I/O 处于 CP 模式，尾部时延也会上升，但低于 CP。

不同完成方式的时延对比（Figure 19: Latency comparison (YCSB B with an 80 ms pulse period). Latency values are normalized to INT.）

为检查是否需要逐设备调参，论文还在 8 块额外 NAND SSD 和 1 块额外 3D XPoint SSD 上运行同一配置。除 SN850X 外，DPAS 在其余 8 块设备上都优于其他方法。

能耗方面，论文未测得各完成方法之间的整机功率差异；在 8 线程、4 个 CPU 的高竞争测试中，CP 累计能耗最高，作者将其归因于更长的执行时间。

六、思考

DPAS 的 CPU 余量与吞吐取舍

DPAS 默认优先提高 IOPS，因此低竞争时会大量使用 CP，牺牲 CPU 余量。作者提出可增加节省 CPU 模式（CPU-saving mode）：关闭经典轮询路径，仅保留 PAS 和中断，接受相对 CP 的 I/O 吞吐损失，以换取 CPU 余量；论文将这部分损失归因于上下文切换开销。

中断合并的运行时边界

DPAS 进入中断模式后没有中断合并机制，并发 I/O 浪涌可能造成中断风暴（interrupt storm）。扩展方案需要能在运行时判断请求的紧迫度；vIC 是面向虚拟机存储 I/O 的中断合并方案，可按在途命令数和当前 I/O 速率调整合并，但目前只在虚拟化环境中验证过，还需在原生系统验证。若能加入动态合并，DPAS 可从普通中断已能满足的中等吞吐负载扩展到更高吞吐、可从中断合并获益的负载。
