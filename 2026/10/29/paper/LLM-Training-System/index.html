大模型训练系统：从一次参数更新到千卡集群

TLDR： 大模型预训练把 token（词元）序列转成预测结果，再通过损失、反向传播和优化器更新参数；分布式训练把样本、张量、层和专家分配给多张 GPU，并在迭代中同步计算结果。FAST、OSDI、SOSP、NSDI 的系统论文沿着这条执行链研究数据供给、流水线负载、异构互连、checkpoint（检查点）和规模化评测。训练系统的效率取决于一轮更新的关键路径，以及长作业中保存和恢复进度的成本。

一、共同问题：让整个训练作业持续前进

大模型训练是一项长时间运行的分布式作业。数千张 GPU 同时处理不同批次或模型分片，训练框架要让数据及时到达、计算和通信按依赖顺序执行，并在所有必要的结果就绪后完成一次参数更新。某个数据分片读取缓慢、某条网络链路拥塞或某个流水线阶段计算更久，都会延长当前迭代；同步作业要等依赖关系上的慢任务完成，其他 GPU 才能进入后续阶段。

因此，理解训练系统需要同时看两层：模型如何从样本计算出参数更新，以及系统如何把样本、模型状态和计算任务放到不同设备上。下文以 decoder-only（仅解码器式）文本预训练为主；微调和强化学习后训练会改变样本组织或训练目标，但仍会复用前向、损失、反向和参数更新等核心环节。

二、抽象模型：一轮迭代如何更新参数

预训练的词元预测目标

分词器把文本切成词元并生成词元编号。embedding（词嵌入）层将编号映射成向量，模型还要表示词元在序列中的位置。一个 decoder-only Transformer 通常叠加多层 Transformer 层；每层先用 self-attention（自注意力）整合可见上下文，再用前馈网络变换各位置的表示。输出层将最终表示映射到词表，为每个候选词元生成 logits（未归一化分数）。

causal mask（用于屏蔽未来位置的掩码）限制每个位置只能使用当前位置及其之前的上下文，因此模型可以在一轮前向计算中并行处理序列里的多个位置，同时为每个位置预测下一个词元。

预训练样本本身提供监督目标：输入位置上的上下文对应原文中的下一个词元。损失函数比较模型给出的分布与真实目标，常用目标是交叉熵。模型参数在多批样本上反复更新，使训练数据中出现的上下文与后续词元之间的关系逐步写入参数。

训练迭代中的参数更新

一次典型迭代依次完成前向计算、损失计算、反向传播和优化器更新。前向计算产生 logits 和中间激活值；损失计算给出当前批次的预测误差；反向传播根据误差计算各参数的梯度；Adam 等优化器结合梯度和自身维护的状态更新参数。训练程序随后取下一批样本，重复这一过程。

训练程序可把一个批次切成多个 microbatch（微批次），逐个计算并累积梯度，再更新参数。每个 microbatch 完成反向传播后即可释放对应激活值，降低单次计算的显存峰值；一次参数更新则要等待这些 microbatch 都完成。数据并行训练中的全局批次量由每个副本处理的 microbatch、数据并行副本数和梯度累积次数共同决定。

训练状态管理与检查点恢复

GPU 显存同时容纳模型参数、反向传播需要的激活值、梯度、优化器状态和临时工作区。序列长度、批次大小、模型宽度和并行方式会改变这些对象的规模与分布。训练系统需要在每张 GPU 的显存容量内安排它们，并控制为交换或重新生成状态所付出的计算和通信成本。

一个检查点通常还要保存恢复作业所需的参数、优化器状态、数据进度及其他元数据。只保存参数能够用于推理，却不足以在原训练位置完整恢复优化过程。

三、参照执行：单卡迭代如何扩展

单卡训练在一张 GPU 上保存模型状态，处理一个批次并完成更新。扩展到多卡后，系统可以沿不同维度拆分工作；一项训练任务通常组合多个维度，而不是只使用一种并行方式。

data parallelism（DP，数据并行）复制模型，让各 GPU 处理不同样本。各副本先计算本地梯度，再通过集合通信（collective communication）中的 AllReduce（归约并把结果分发给组内成员）聚合梯度，随后更新参数。标准 DistributedDataParallel（DDP）在每个 worker（训练进程）上保留完整模型副本；副本数量增加了样本吞吐，也会重复占用模型和优化器状态的显存。

Fully Sharded Data Parallel（FSDP，完全分片的数据并行方式）把参数、梯度和优化器状态分散到数据并行组的多个 worker。执行某一层时，worker 按需 AllGather（收集并拼接）参数分片；反向计算后，ReduceScatter（归约后分发梯度分片）并更新各自负责的状态。分片降低单卡状态占用，也增加参数收集和梯度分发的通信。

tensor parallelism（TP，张量并行）把单层中的矩阵运算拆到多张 GPU；pipeline parallelism（PP，流水线并行）则把连续的模型层分配到不同阶段，让多个 microbatch 在阶段之间流动。TP 会在层内引入通信，PP 把模型状态分散到多个阶段，但阶段启动和排空时会出现 bubble（流水线空泡）。长序列训练还可用 context parallelism（沿序列维度切分上下文）分摊上下文计算。

MoE 模型把多个专家网络放在同一层，由路由器为每个词元选择要执行的专家。expert parallelism（EP，专家并行）将专家放到不同 GPU，路由器需要把词元发送到对应设备，再收集专家输出；这种分发和回收使用 All-to-All（各参与进程彼此交换数据）通信。DP、TP、PP、EP 和 context parallelism 可以组合，系统则需要共同安排各组 GPU、通信路径和显存状态。

四、约束驱动的系统设计

大模型训练的数据路径

稳定的训练批次要经过存储读取、解码或转换、组批、CPU 内存暂存，再传到 GPU。训练启动时还要读取参数和优化器状态；运行中需要写检查点；独立评测任务会读取最近的检查点。存储和数据加载因此参与训练作业的完整生命周期。

OSDI ’26 的 Teaching the Old Dog New Tricks 分析了生产预训练任务的数据访问，指出远程评测读取检查点会受到跨数据中心小块读取时延影响，训练启动时的检查点读取会争用存储输入/输出（I/O），多模态样本转换则可能受 CPU 处理能力限制。它把存储访问、数据加载和评测纳入大模型训练的数据路径。

预训练数据管道与伴随评测（Figure 1: Data Pipeline in Pre-training）

异构 MoE 训练的流水线优化

PP 把模型层分配给多个阶段，再让 microbatch 依次经过这些阶段。阶段耗时若不均衡，较快的阶段会等待较慢阶段；MoE 路由又会让不同 GPU 在不同迭代中接收不同数量的词元，产生额外 bubble。不同注意力层与 MoE 层的计算量、通信量也可能不同，按层数或串行计算时长平均切分，不一定能平衡实际执行时间。

Qwen3-Next 每四层交错使用三层 Gated DeltaNet 线性注意力和一层标准 softmax 注意力，每种注意力层后都接稀疏 MoE。不同层组合的计算量和 All-to-All 通信量因此不同。

Qwen3-Next 的混合注意力层组成（Figure 1: Heterogeneity in Qwen3-Next Architecture. (a) standard Transformer layer; (b) Qwen3-Next interleaves Gated DeltaNet and standard attention layers.）

OSDI ’26 的 Tessera 面向 Qwen3 与 Qwen3-Next 的异构 MoE 训练，先为不同层组合测量计算与通信重叠后的成本，再据此选择流水线分区；运行时则根据路由信息，将可延后的梯度计算填入预测到的 bubble。Tessera 交错执行不同 microbatch 的计算与通信，以隐藏部分通信等待。

跨 microbatch 的通信与计算重叠（Figure 2: Mechanism of Inter-Microbatch Overlap. The bottom panel illustrates how the backward pass of Chunk B is overlapped with the forward pass of Chunk D by interleaving decomposed operations.）

异构拓扑下的集合通信调度

AllReduce、AllGather、ReduceScatter 和 All-to-All 都需要多个 worker 按共同步骤交换数据。集群中的 GPU、网卡和链路可能具有不同带宽；一个通信步骤如果等待最慢链路，较快链路便无法持续传输。固定的环形或树形模板难以让每种异构拓扑都获得均衡的传输时长。

NSDI ’26 的 HeteCCL 从集群拓扑和链路带宽生成集合通信计划。它将链路传输切分为可并行调度的数据块，把每个调度步骤中的传输时长纳入搜索，再生成可执行的通信算法。合成器还用 counterexample-guided inductive synthesis（CEGIS，反例引导归纳综合）根据违反约束的传输步骤补充约束，迭代缩小候选计划范围。

HeteCCL 的集合通信计划生成流程（Figure 3: Overview of HeteCCL. HeteCCL inputs the heterogeneous topology description, converts it to an intermediate representation, and builds a quantified link model with formal constraints. The synthesizer uses CEGIS to generate the optimal collective communication algorithm, which is then deployed by the backend.）

并行训练中的检查点冗余

训练作业运行时间长，设备或进程故障会让分布式训练从最近一次一致的检查点恢复。检查点保存越频繁，故障后需要重算的训练进度越少；检查点写入的 I/O 和同步成本也会更频繁地进入作业时间。

FAST ’26 的 AdaCheck 观察到，并行策略、模型结构和训练迭代会让不同 worker 持有重复的张量状态。它识别参数与优化器状态之间的冗余，只保存恢复训练必需的状态，并利用相邻迭代之间的状态变化进一步缩小检查点。

AdaCheck 利用状态冗余生成缩减检查点（Figure 5: AdaCheck overview.）

大规模训练的执行图混合仿真

小规模训练可以验证代码，但缩小 GPU 数量、批次和并行度会改变通信组、显存布局和流水线行为；纯仿真则只能重现模型显式描述的因素。要判断生产规模下的迭代时间、显存峰值或通信交互，评测系统需要保留与目标配置有关的执行依赖。

SOSP ’26 的 CrystalLLM 用少量真实 GPU 执行目标 rank（分布式训练进程）的代码，并让虚拟 rank（由执行图模拟的进程）重放计算时序和通信参与。论文用这一机制评估数百到数千 GPU 的训练配置，关注目标 rank 与其他 rank 的通信关系和时间依赖。

CrystalLLM 的执行图准备与混合仿真（Figure 1. System overview. Phase 1 (graph preparation, §4) collects the bare graph via context switching (Stage 1) and fills and calibrates timing (Stage 2) to produce the execution graph. Phase 2 (hybrid emulation, §5) runs the ranks of interest on sandbox GPUs while virtual ranks replay the graph on assistant GPUs.）

五、论文评测呈现的系统收益

下表按论文分别列出评测对象与报告结果。每项结果对应不同的工作负载、硬件和指标，需结合其评测条件解读。

论文评测对象论文报告
Teaching the Old Dog New Tricks（OSDI ’26）生产预训练数据路径；分析 90 天内采集的 3 万个训练作业运行记录配套优化将每次评测浪费的 GPU 时间从 16,800 小时降至 4,000 小时；训练启动时检查点加载时间缩短 40.8%，数据加载造成的训练停顿减少 63.2%
Tessera（OSDI ’26）Qwen3/Qwen3-Next 的五组生产训练负载，使用 4,096–12,288 张 NVIDIA Hopper GPU相比生产基线，训练吞吐提高 20%–33%；其中一个万亿参数配置达到 39% MFU（Model FLOPs Utilization，模型 FLOPs 利用率）
HeteCCL（NSDI ’26）由 H20 与 V100 GPU 组成的异构测试集群集合通信带宽相对 NCCL、TACCL、TE-CCL 分别最高提高 2.8×、4.4×、2.6×；端到端训练效率提高 23%–37%
AdaCheck（FAST ’26）多种稠密与稀疏模型、规则与自动生成的并行策略相对已有检查点方法，论文报告检查点体积的缩小倍数为 6–896×，保存频率提高 1.46–111×
CrystalLLM（SOSP ’26）Qwen3 MoE 在 512–2,048 GPU 目标配置上的仿真评估迭代时间预测平均误差 0.58%、最大误差 1.98%；峰值 GPU 显存估计误差低于 0.01%

六、整体运行机制：关键路径贯穿整轮迭代

一次训练迭代从数据读取和组批开始，经过前向、损失、反向与梯度通信，再由优化器更新参数；若达到保存间隔，训练框架还要写出可恢复的检查点。独立评测可能在训练运行期间读取某个检查点。计算、通信、存储和评测由不同软件层执行，却共享 GPU、CPU、内存、网络和存储资源。

并行策略决定工作如何拆分，通信库决定分片如何交换，数据管道决定 GPU 是否拿得到下一批输入，检查点系统决定故障后要重做多少训练。MoE 的动态路由、异构链路和多模态输入又改变每轮实际负载。
