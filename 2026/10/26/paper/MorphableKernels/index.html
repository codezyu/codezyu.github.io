MorphX：用 morphable kernel 实现 GPU 多任务调度

论文：Efficient GPU Multitasking with Morphable Kernels，Tingxu Ren、Ruwen Fan、Hao Guo、Minhui Xie、Shiwei Gao、Jiwu Shu、Youyou Lu，SOSP ’26。DOI：10.1145/3830418.3843904。

TLDR： 已启动 kernel 的流式多处理器（SM）分区固定，kernel slicing 只能靠逐片启动调整；异步执行又让 host 难以感知当前运行负载。MorphX 用编译期改写的 morphable kernel 实现 SM 让出与收回，并以 wave latency 在线估计资源需求，驱动吞吐或隔离分区。在 NVIDIA A100 共置实验中，同等 LLM P99 TPOT 下 ANNS 吞吐较 Orion 最高提高 2.24×；Qwen2.5-7B prefill/decode 共置时，P99 归一化请求时延较 vLLM 最高降低 70.6%。

一、背景：GPU 任务的资源互补

GPU 由多个 Streaming Multiprocessor（SM，流式多处理器）组成。每个 SM 有自己的计算单元、寄存器和共享内存，高带宽内存（HBM）、L2 cache 与 PCIe 则由 SM 共享；NVIDIA A100 有 108 个 SM。一个 kernel 通常包含许多 thread block（线程块），硬件调度器把它们分配到 SM 上执行。thread block 一旦开始运行，就不能迁移到另一个 SM，必须等执行完成。

GPU 硬件结构与编程模型（Figure 2: GPU hardware architecture and programming model. A GPU device is composed of multiple SMs, each with its own compute units, registers, and shared memory. HBM, L2 cache, and PCIe are shared. Kernel 0 and Kernel 1 occupy 𝑆𝑀0,1 and 𝑆𝑀2,3, respectively. Reg: Register file. Sh. Mem: Shared memory.）

单个 kernel 往往受计算能力或内存带宽限制，另一类资源没有用满。把计算密集型和内存密集型任务放到同一块 GPU 上运行，可以利用这种互补性；但任务的资源需求也会随执行阶段变化。例如，batch size 较大（≥ 128）的 LLM serving 中，attention 通常受内存带宽限制，前馈网络（FFN）层则主要受计算能力限制；混合专家模型（Mixture of Experts，MoE）的 all-to-all 操作主要占用互连带宽，因而使 GPU 的计算能力得不到充分利用。

二、现状：现有调度在灵活性与开销间取舍

best-effort 方法用 CUDA streams 安排 kernel 的提交顺序，但 thread block 如何落到 SM 上仍由硬件决定，不能保证互补负载并行执行。静态分区方法在启动 kernel 前分配 SM，运行期间不能调整；负载变化后，固定分区可能使部分 SM 处于闲置状态。GPU kernel preemption 可以抢占 kernel 占用的 SM，但现有方法忽略 kernel 的计算和内存带宽需求，因此不能据此安排资源互补的共置任务。

kernel slicing 把一个 kernel 切成多个片段，每个片段单独启动，因而能在片段之间重新分配 SM。代价是每个片段都要额外启动 kernel 并与 host 同步。论文测得单次 kernel launch 的开销超过 10 µs；在其测量中，激进切片使矩阵乘法延迟增加到原来的 5.317 倍。

GPU 多任务调度方法的资源控制与开销取舍（Figure 1: GPU task scheduling methods. Best-effort methods cannot explicitly allocate SMs or memory bandwidth, while kernel-wise static methods support only rigid allocation, resulting in low resource utilization. Kernel slicing methods enable fine-grained scheduling, but incur frequent extra kernel launches and thus introduce high scheduling overhead. Morphable kernels adjust SM allocation without extra kernel launches.）

三、问题：运行时 SM 控制与资源观测缺位

论文明确了两项待解缺口：软件无法在已启动 kernel 中调整 SM 占用；调度器也无法低开销、及时地获得执行状态和资源需求，支撑逐时刻的分区决策。

3.1 已启动 kernel 的 SM 占用无法动态调整

GPU 没有中断机制或运行中的 kernel 控制接口。kernel 启动后，硬件调度器决定 thread block 的位置；block 在完成前不能迁移，软件也就无法收回它所在的 SM。设置 SM affinity 只能限制启动时的分配，执行期间仍然固定。kernel slicing 只能在片段边界重新分配 SM；由于每个片段都要单独启动 kernel，这种调整还需要额外的 launch 和 host 同步。因此，负载阶段改变时，已启动 kernel 的 SM 占用仍锁定在原分区。

作者用三个 CUTLASS GEMM 算子观察计算密集型与内存密集型 kernel 的共置。当时 MorphX 尚未实现，作者用 CUDA Green Context 对不同 SM 配置分别 profile，再拼接测量结果。这组负载的静态最优分区为 3:1；计算密集型 kernel 结束后，内存密集型 kernel 仍保持共置时的 SM 配额，原分给计算密集型 kernel 的 SM 因而闲置。负载阶段改变后，先前测得的最佳固定比例无法继续匹配当前负载。

不同调度机制下的 SM 指令与 DRAM 带宽利用率（Figure 3: Resource utilizations when applying different mechanisms. Morphable kernel shows promise in increasing utilization of both SM and memory bandwidth resources with the ability of on-the-fly adjustment. Bars show execution intervals and curves show resource utilization. (MI: memory-intensive. CI: compute-intensive.)）

3.2 调度器无法实时识别执行进度与资源需求

即使能够改变 SM 分配，调度器仍需知道哪些 kernel 正在运行或排队、执行到哪里，以及它们受计算能力还是内存带宽限制。CPU 与 GPU 异步执行，host 不知道当前哪个 kernel 正在设备上运行；GPU 也没有低开销的在线资源跟踪接口。CUPTI 主要用于离线 profile，二进制插桩又不适合持续监控。缺少实时状态和需求估计，调度器就无法及时判断共置任务是否互补，也无法选出能利用资源或限制争用的分区。

四、方案：MorphX 的 kernel 改造与在线分区调度

针对问题一，MorphX 用编译期转换把普通 kernel 变成可动态调整 SM 占用的 morphable kernel；针对问题二，它通过 kernel 接口观测执行进度，再用 wave latency 建立资源需求模型。host 侧调度器依据这些估计，为正在运行和即将运行的 kernel 选择 SM 分区。CUDA API 由运行时拦截，各 stream 的 kernel 元数据保存在 host 队列中。

MorphX 的运行时架构（Figure 4: MorphX architecture overview. MorphX is non-intrusive and adapts to various GPU applications. The compiler transforms kernels, while the interceptor and scheduler use micro-interfaces and an online model to adjust SM allocation.）

4.1 kernel 编译改写与选择性启用

针对问题一，MorphX 的关键观察是 thread block 可以作为最小调度单元，在不改变程序语义的前提下重新映射到不同 SM。系统通过 LLVM 中间表示（IR）pass 在编译期改写 kernel，不要求用户修改源代码：内联 __device__ 函数，为 __global__ 函数加入 fetched、finished、minSM 和 maxSM 等 micro-interface，把 kernel 主体包进领取 thread block 的循环，并重映射 blockIdx、gridDim 和 return。每个 thread block 的调度逻辑只由一个 leading thread（首线程）执行。

编译产物同时保留原 kernel 和 morphable kernel 版本。每次启动时，MorphX 根据 profile 估算改写版本的相对开销；超过预设阈值就启动原 kernel，否则运行 morphable kernel。这样，短 kernel 可以继续走原路径，较长的主要 kernel 才进入运行时资源调整。

LLVM pass 的 kernel 编译期转换（Figure 7: Compile-time kernel transformation. The transformation is implemented via an LLVM pass, requiring no manual modification to the code. The numbered steps inline functions, add micro-interfaces, wrap the body in a work-fetching loop, remap indices, and redirect returns.）

4.2 micro-scheduler 让出 SM，reclaim queue 补上收回

每个 SM 上运行一个 micro-scheduler，从 kernel 的共享工作池中领取 thread block。它通过原子递增全局计数器 fetched 取得下一个 block，再把编号映射回原 kernel 的三维索引。host 调度器用 minSM 和 maxSM 指定允许该 kernel 使用的 SM 范围；范围外的 micro-scheduler 会先完成当前 block，再停止领取新 block。kernel 的其余部分继续执行，因此让出 SM 不需要重新启动 kernel。

micro-scheduler 在运行中让出 SM（Figure 5: Yielding SMs on the fly. fetched represents the global index increased by the micro-schedulers to fetch thread blocks. Reducing maxSM from 2 to 1 makes SM1 quit after its current block while SM0 continues, releasing SM1 without relaunching the kernel.）

让出机制本身不能收回已经释放的 SM：若把恢复执行的 kernel 放回原 stream，排在前面的异步 kernel 会造成 head-of-line blocking。MorphX 因此创建优先级高于用户 stream 的内部 reclaim queue；需要收回时，它启动一个共享原 kernel fetched、finished 计数器的实例，继续消费同一工作池。这个队列补上收回路径并绕过原 stream 的队头阻塞，但会增加 kernel launch；额外启动次数不超过原 kernel 数，总启动次数至多为原来的两倍。

reclaim queue 消除回收 SM 时的队头阻塞（Figure 6: SM reclaiming. To reclaim SMs, the same kernel is launched in the reclaim queue with the same fetched and finished pointers. The high-priority 𝐾′0 reuses SMs released by 𝐾1 while 𝐾2 proceeds, avoiding head-of-line blocking (left); without the queue, 𝐾2 waits (right).）

4.3 运行进度观测与资源强度估计

针对问题二，MorphX 让设备侧接口暴露执行进度：GPU 在领取和完成 thread block 时更新 fetched 与 finished，host 写入 minSM 与 maxSM。四个整数位于 device memory，host 通过 GDRCopy 读写，不占用 GPU compute units。MorphX 按 stream 维护 kernel 元数据队列，由后台 host thread 轮询进度；平均每次约 10 µs、读取 8 bytes，对应 PCIe 带宽约 0.8 MB/s，低于现代 GPU 约 25 GB/s 的峰值带宽。

接口提供进度，但还需要从中估计资源需求。MorphX 用 Roofline model 解释 SM 配额变化：减少 SM 会降低计算峰值，却不会按同一比例降低 HBM 带宽。per-wave latency 随 SM 配额的变化可显示 kernel 由计算受限转为带宽受限的转折，并据此拟合归一化 compute intensity；模型再用 memory intensity 量化 kernel 的带宽需求。

SM 配额改变计算与带宽受限区域（Figure 8: (a) Original Roofline Model. Reducing SMs lowers the compute ceiling, changing an MI kernel to compute-bound. (b) Performance of different kernels when allocated increasing SMs. The turning point represents the normalized compute intensity. MI: Memory-intensive kernel. CI: Compute-intensive kernel. CB: Compute-bound phase. MB: Memory-bound phase.）

kernel 首次执行时，MorphX 逐 wave 减少分配的 SM 数量，同时保持 thread block 总数不变，再拟合 wave latency。对内存密集型 kernel，这些测量可估算 compute intensity。计算密集型 kernel 的强度不能从独立执行中推得，MorphX 先将其设为 1；之后将它与内存密集型 kernel 共置，根据后者的 slowdown 修正估计。由于该内存密集型 kernel 受带宽限制，论文用它在重叠 wave 中的 slowdown 估算额外的内存争用。论文指出首次 profile 最多使 kernel slowdown 达到 2×，且只发生在初次执行。

按 wave latency 做在线 profile 与强度修正（Figure 9: In-place profiling and refinement. MorphX measures the per-wave latency to derive the compute intensity of a kernel. (a) Normal waves; (b) profiling with fewer SMs per successive wave; (c) 𝐾𝑚 slowdown refines the demand estimate for 𝐾𝑐.）

4.4 吞吐、带宽隔离与用户定制策略

吞吐导向策略根据共置 kernel 的 memory intensity 分配 SM。对两个 kernel，MorphX 求解 n_p + n_q = 1 与 n_p I_p^m + n_q I_q^m = 1，分别保证 SM 总份额为 1、合并后的带宽需求能用满目标带宽；低于 1 表示带宽未充分利用，高于 1 表示争用。由于 host 与 GPU 通信有延迟，调度器检查每条 host 队列前两个 kernel，并在下一 kernel 开始前预计算分区。

MorphX 还提供面向性能隔离的 Memory Bandwidth Isolation：高优先级任务可指定希望获得的计算资源和内存带宽份额，调度器限制其 SM 数量以满足约束。用户也可为 stream 指定期望的 SM 占比；冲突时，MorphX 优先满足较晚启动的 kernel。三类策略分别面向资源利用、性能隔离和用户定制。

五、结果：共置吞吐、尾延迟与监控开销

实验使用双路 Intel Xeon Gold 5420+、256 GB DRAM 和 NVIDIA A100 40 GB；软件环境为 PyTorch 2.6.0、vLLM 0.8.1、FlashInfer 0.2.2 和 Clang 21.0.0。由于 PyTorch 使用的 cuBLAS 闭源，作者以 CUTLASS 算子替代。

5.1 多任务共置下的后台吞吐与前台干扰

前台为 vLLM 运行的 Llama-3-8B，请求来自 ShareGPT 并按 Poisson 分布到达；后台任务为 ANNS（approximate nearest neighbour search，近似最近邻搜索）或矩阵乘法（MM），请求率逐步增加。指标是前台 P99 TPOT（第 99 百分位的每输出 token 时延）和后台每秒完成的操作数。对照包括 NVIDIA Multi-Process Service（MPS）的 3:7 和 1:1 分区、CUDA stream、跨 context 的 Timeslice、TGS、Orion，以及使用 kernel slicing 的 LithOS。

在相同 LLM P99 TPOT 下，MorphX 的 ANNS 吞吐较最佳对照 Orion 最高提高 2.24×。作者将增益归因于 MorphX 按运行时需求调整 SM 分区，提高资源利用率并控制争用。

ANNS 后台吞吐与 LLM P99 TPOT（Figure 10: ANNS throughput vs LLM P99 TPOT. Upper-left is better.）

对矩阵乘法后台负载，MorphX 在多数测试点的吞吐高于对照；有一个点由 MPS 1:1 取得更高吞吐，因为该分区为 LLM 保留了足够的 SM，但代价是矩阵乘法最高吞吐降低。

矩阵乘法后台吞吐与 LLM P99 TPOT（Figure 11: MM throughput vs LLM P99 TPOT. Upper-left is better.）

LLM 请求率为 4 req/s 时，MPS 3:7 的 P99 时延是 MorphX 的 2.75–3.53 倍。TGS 和 Orion 不能抢占 ANNS kernel 已占用的 SM，因而可用于缓解干扰的调度空间受限。

ANNS 查询压力下的 LLM P99 时延（Figure 12: LLM P99 latency under different background task pressure. Lower is better. This shows MorphX’s efficiency in interference mitigation. Panels use LLM rates of 1 and 4 req/s, with ANNS pressure increasing along the x-axis. MorphX keeps tail latency stable as pressure rises.）

5.2 LLM 共置时延与资源模型评估

LLM serving 实验把 vLLM 的 prefill 与 decode 放入不同 stream 并移除两者依赖，使两个阶段可在同一 GPU 上共置。测试 Llama-3-8B 和 Qwen2.5-7B，请求按 Poisson 分布到达；输入／输出长度为 2048／256、4096／128、4096／256。端到端请求时延从请求到达到生成最后一个 token 计算，并按输出 token 数归一化，比较平均值和 P99。

在上述三组输入／输出长度下，Qwen2.5-7B 的 P99 归一化请求时延相较 vLLM 分别最多降低 70.6%、58.0% 和 52.1%；Llama-3-8B 分别最多降低 48.4%、36.1% 和 47.0%。随着请求率提高，不同请求的 prefill 与 decode 更可能重叠，MorphX 可利用两阶段的资源互补性调整 SM 分配。

Qwen2.5-7B 的平均与 P99 归一化请求时延（Figure 13: Qwen 2.5 7B average & P99 request latency. Lower is better.）

Llama-3-8B 的平均与 P99 归一化请求时延（Figure 14: Llama 3 8B average & P99 request latency. Lower is better.）

监控分析中，Llama-3-8B 工作负载有 26 种 kernel 实现，其中 5 种首个 wave latency 超过 50 µs，合计占 GPU 执行时间的 85%；MorphX 只对这 5 种启用转换与监控。NCU 的开销为基准的 2.23–1590 倍，NvBit 超过 409 倍；MorphX 在所有工作负载上的开销低于 5%，在 GEMM 和 GGNN 上低于 0.5%。

不同资源监控方法的相对延迟开销（Figure 15: Overhead of different resource monitoring methods. The latency is normalized and shown on a logarithmic scale. Base is 1×; lower is better. NCU and NvBit incur orders-of-magnitude overhead, whereas MorphX adds less than 5%.）

模型评估使用 N = K = 65536、M 分别为 16、512、8192 的矩阵乘法。两个内存密集型 kernel 的归一化 compute intensity 分别为 0.247 和 0.753，计算密集型 kernel 为 1.19。当计算密集型 kernel（M = 8192）与内存密集型 kernel（M = 16）按 1:1 共置时，后者的 wave latency 增加 43%；MorphX 据此修正前者的 compute intensity。

Kernels are matrix-matrix multiplication with N=K=65536 and varying M. Markers are measurements and lines are model fits; (a)–(b) show memory-intensive turning points, while (c) shows a compute-intensive kernel.）
